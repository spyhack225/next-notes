1. **P1 — The transport and counter must be ported to no-Apple before integration.** `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:99` exposes `appleSynthesisCallsForTesting` through `AVSpeechBacking`; lines 109 and 115 use that backing for prepared playback and cancellation. `Voice/VoiceDiagnosticSpeech.swift:40`, `Voice/VoiceAcknowledgementSelfTest.swift:22` and `Voice/VoiceLatencySelfTest.swift:148` depend on the Apple-only getter. Current `claude2/no-apple` (`e728d84e`) deletes this backing and exposes the instance property `speechSynthesisCallsForTesting`, which counts permitted Pocket/Kokoro requests. Renaming the getter while retaining zero-call assertions would incorrectly fail legitimate speech. Map prepared playback onto its existing `PreparedPCMSpeechBacking`, preserve receipt/token/generation fencing, and replace the obsolete assertions with the neutral counter's actual semantics plus a forbidden-sink census. The two direct Pocket `session.enqueue` calls at `Voice/VoiceAcknowledgementClips.swift:173` must enter the existing synthesis-request census; disk restoration and PCM playback must not. The acknowledgement itself does not call Apple text synthesis, but its current transport implementation cannot simply survive the no-Apple merge. Do not restore the deleted sink to make it compile.

2. **P2 — Optional clip preparation bypasses the new resource admission policy.** `Sources/NextNotes/Agent/Voice/VoiceAcknowledgementClips.swift:130` calls `PocketAgentVoice.prepare()` / `KokoroAgentVoice.prepare()` directly. Its idle guard excludes current conversation/dictation/meeting activity, but supplies no pressure or ASR compute admission. No-Apple now distinguishes explicit preparation from `prepareAutomatically()` and gates optional work on pressure, recording and the existing scheduler. A mechanical merge leaves courtesy preparation using the explicit route, defeating that protection. Use the automatic route and the same availability owner, and require actual `AgentSpeechSynthesizer.availability == .ready` together with exact selected engine/voice identity. `Selection.ready` at line 22 currently checks only backend `isReady`, which cannot represent all no-Apple failure states. Normal startup and stressed-machine admission were not exercised by the warm, manually prepared harness.

3. **P2 — Cancelling prewarm does not retire its native producer through the reply owner's join.** `Sources/NextNotes/Agent/Voice/VoiceAcknowledgementClips.swift:84` only cancels the cache task. That task obtains an independent reply session at line 167 and eventually joins it at line 185. Meanwhile the normal answer uses `PocketAgentVoice.startReplyPlayback` (`Speech/PocketAgentVoice.swift:39`, `:465`), whose predecessor slot contains answer playback tasks, not this cache task. Resumed input or a ready answer can therefore cancel optional work and admit answer synthesis while the cancelled courtesy session is still draining native work. The late join prevents stale cache publication, but does not establish exclusive native ownership or absence of resource contention for the answer. The held-render test proves cache/termination ownership, and the timing harness prepares both clips before any turn; neither tests this transition against actual answer synthesis. Put optional native rendering under the existing speech producer's cancellation/admission ownership and verify a held prewarm -> resumed input -> immediate answer transition. Keep the commit path free of a blocking join, new queue or lock. I did not establish a crash or measure a latency penalty; the uncovered ownership transition is the finding.

4. **P2 — The first native refusal remains possible and production diagnostics cannot attribute it.** `Sources/NextNotes/Agent/Voice/VoiceAcknowledgementClips.swift:225` logs only “Acknowledgement clips unavailable”; detailed stage/domain/code tracing is confined to a self-test switch. `Tests/Reports/voice-ack/after-ack.log:2` retains the actual initial ABSENT, before turns. Later success did not change or explain that path. Native final clips contain 46,080 and 36,480 samples (1.92 s and 1.52 s), close to the unchanged 48,000-sample refusal bound; earlier successful clips were much shorter. Oversized/silent/nonfinite output, I/O errors or native failures can still take this path. This does not prove the original cause was length. On failure the user gets no courtesy sound, no added reply or visible failure, and the ordinary answer continues; the harness instead exits ABSENT. A non-cancellation failure does not itself rearm preparation: another session/state/output-completion event must retry it. Retain bounded clips and silent failure, but retain a privacy-safe production reason/stage and qualify retry/recovery at an existing idle event. Hear the actual clips before calling them short, content-free courtesy sounds; START timing does not measure their quality or duration.

5. **P2 — The fallback-spy test does not observe the installed fallback.** `Sources/NextNotes/Agent/Voice/VoiceDiagnosticSpeech.swift:7` accepts `fallbackSpy` but always installs a new `Silence()` instead. `contractProblems` checks `apple.spoken` at line 21 even though that recorder was never installed. This guards against a future implementation using the supplied recorder, but would miss a regression that selects the real system fallback without using that argument. The actual Apple entry counter is not compared inside these forced-failure cases; the native successful-run counter is separate evidence. Observe the fallback actually installed, check its drops and the real prohibited entry census, and show that substituting a prohibited-sink stand-in makes this fixture fail. Do not inject forbidden synthesis into production.

6. **P3 — The new timing gate enforces a median, not a per-turn deadline.** `Sources/NextNotes/Agent/Voice/VoiceLatencySelfTest.swift:282` requires all measurements to exist but compares only median ACK to 200 ms. It would pass some late acknowledgements. All five retained final turns are actually below the deadline (116–129 ms), so this is not a false result for this run. If PL-12's “within 200 ms” is a per-turn acceptance requirement, enforce that in this new gate as well as reporting the distribution. No pre-existing latency threshold or test body was weakened in the acknowledgement diff; the original 39-case fixture is unchanged, and the actual cleaned-input/output-completion REDs are retained.

The playback path is `VoiceConversationCoordinator.swift:540` -> `OutputScheduler.swift:137` -> independent 40 ms grace -> scheduler turn/session validation at `:141` -> `RealtimeAudioSession.swift:202` -> `VoiceAcknowledgement.swift:102` -> existing synth prepared playback. No new AVAudioEngine/player, courtesy queue or lock is introduced. The grace is a separate Task and is not awaited by the answer. File I/O, PCM validation and splitting run before commit, although they still perform synchronous work on MainActor during the idle preparation task. Two clips retain at most 384,000 bytes of float PCM payload plus buffer/object overhead; temporary rendering also allocates. Disk files are keyed by schema/engine/voice and survive invalidation; the code has no acknowledgement-specific eviction, so “two clips” is a per-selection memory bound, not a lifetime two-file disk bound.

Cancellation at ordinary answer admission is synchronous (`OutputScheduler.swift:150`), before preparation, and invalidates the grace revision. Fixed/sessionless/delivery starts also cancel courtesy. Stopping playback invalidates backing tokens, so stale callback tasks cannot restart it. I found no source path in these entries that starts an old acknowledgement over or after the admitted answer's first audio. Resumed cleaned energy cancels immediately (`Activation/AgentCaptureController.swift:1900`) without changing the ordinary 120 ms answer-floor condition. The semantic speaking floor, reply/history/delivery callbacks and text echo ledger are bypassed, and `noteUserSpeech` excludes courtesy from barge counting (`RealtimeAudioSession.swift:660`). The existing transport installs `VoicePlaybackReference`, so acoustic echo reference remains. Dictation and meetings suppress admission and preparation. These are source/control conclusions; absence of a text echo entry is not proof that a physical room cannot transcribe or react to clip leakage.

Measurement is honest within its stated scope. `after-ack-final.log:849` reports ACK median 120 ms, nearest-rank p95/max 129 ms, min 116 ms, n=5; line 850 reports PASS. The receipt is the first played 10 ms buffer, after the committed endpoint, rather than microphone speech end or answer audio. About one second of endpointing precedes it. L2/L3 remain separate: no-ACK medians 2.635/2.792 s, ACK 2.941/3.065 s. This is not a 120 ms answer, a Kokoro result, or a real-microphone/room result.

The comparison uses the same pinned release binary and authored WAV, one excluded warm-up and five counted localEOU turns per arm. It is a reasonable warm on/off comparison, but the ACK arm additionally renders two clips before turns and runs with cache tracing; no-ACK runs first, replies vary, and cold warm-ups differ (VAD versus localEOU). It does not isolate cold-start/preparation cost, establish statistical equivalence, or attribute the higher answer medians to ACK. I found no changed old timeout, grader or latency limit in the reviewed diff. `VOICE_LATENCY_OK` is not evidence that the old 200 ms L1/L2 targets passed.
