## Findings

1. **P2 — The new epoch check discards a legitimate failure of the current reply, leaving its output unsettled.** `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:747`, especially `:749`; preparation changes identity at `:177`, while the reply captures it only at `:360`.

   Start a Pocket or Kokoro reply, then change the selected engine while its synthesis is suspended, without beginning a replacement reply. Alternatively, call explicit preparation for the same cached-ready engine while that reply is still running. Neither action stops or replaces this output, but each changes `selectedVoiceRequest`. When the current backing fails with the still-current playback token, the new equality guard returns before **all** settlement: no interrupted clause receipts, no `replyCanSpeak=false`, no failed output snapshot, no lifecycle release and no `noteOutputFinished()`.

   Both production backings stop themselves before calling this callback (`PocketAgentVoice.swift:696`, `KokoroAgentVoice.swift:287`); they do not then emit normal completion. The synthesizer therefore retains its current clause and queued clauses after physical playback has stopped. For Pocket, subsequent streamed clauses can still enter the synth's reply queue while the stopped backing rejects them (`PocketAgentVoice.swift:581`). The audio session can retain its speaking/output state, and delivery does not settle as text-only. This violates the failure contract even when ignoring the old request for the *new selected voice's global failure latch* is correct.

   Keep current-token/text validation as the output settlement fence. Use the request epoch only to decide whether that failure may latch the current selected voice; always settle the failed current output through the existing owner. Add a held reply failure delivered **after** selection/preparation changes, with queued and subsequent streamed text, and assert interrupted/unheard receipts, cleared lifecycle/audio state, no replay or voice switch, and unchanged recovered/new-selection availability. `VoiceFailureEpochSelfTest.swift:40` delivers its concurrent reply failure **before** retry, then delivers the old **file** error afterward; it does not exercise this regression. This finding is source-derived, not a reviewer-run reproduction.

2. **P2 — The census still misses simple shell command strings and stdin-only `exec say`.** `Tests/Reports/no-apple/check-sink.py:8`, `:9`, `:10`, `:52`; retained mutations at `Tests/Reports/no-apple/review-fixes/test-census.py:5`.

   Ordinary Swift/C receives only the first three patterns. A Swift `Process` with executable `/bin/sh` and arguments `["-c", "say Hello"]`, or a C `system("say Hello");`, contains neither a forbidden API/path nor the exact quoted token `"say"`. It passes these patterns without renaming or obfuscation. The shell script `printf 'Hello' | exec say` also escapes: the command-position expression sees `exec` after the pipe, and the older expression requires an argument after `say`. The 21-case fixture includes `exec say Hello`, which has that argument, but does not combine `exec` with stdin/end-of-line synthesis.

   Recognize shell command strings in source and supported shell wrappers with argumentless/stdin commands, retaining exact bounded exceptions. Add those forms to the mutation fixture with the existing exit1 plus FAILED-marker requirement. Renamed literal API routes and the originally reported `["say", "Hello"]` / direct `| say` escapes are now caught. No new shipping Apple sink was found in this delta; the retained zero-hit marker proves the implemented scan, not complete protection against these forms. These new escapes were established by inspecting regex/control flow, without executing mutations.
