# Review: claude2/no-apple

**Verdict: APPROVE WITH FIXES.** The shipping Apple synthesis sink and its acoustic diagnostic constructors are removed. The central reply selector implements ready-only, selected-voice playback and text-only failure settlement. Fix the production resume gap, failed-voice bypass/recovery contracts, and startup admission before treating the combined voice feature as accepted.

Reviewed `a31dbf7a3d1f03796cea29bd92872de6a93e7970` against `55d402ee3778e7b2204e969adec9c5108c2b192a`. Read BRIEF/RULES-2, the original voice audit, no-apple BRIEF/RESULT, committed reports and production/test code. Read-only review: no build, self-test, model load, GUI, installation or owner-store access. Line numbers below refer to the reviewed branch unless another branch is named.

## Findings

1. **P2 — Production allowed voices cannot satisfy the retained post-resume contract.** `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:465,474,590`; `Sources/NextNotes/Agent/Speech/PocketAgentVoice.swift:369,684,749`; `Sources/NextNotes/Agent/Speech/KokoroAgentVoice.swift:118`; `Sources/NextNotes/Agent/RealtimeAudioSession.swift:102`; `Sources/NextNotes/Agent/Duplex/VoiceContracts.swift:309,319`. Play a ready Pocket/Kokoro reply, pause on a provisional utterance, then discard a harmless backchannel and resume. Both production backings resume their players, but neither conforms to `AgentReceiptSpeechBacking`. Consequently no resume binding/receipt clears `voiceResumePending`; the retained output stays `awaitingResume` and the shadow projects listening while audio plays. A later ordinary first-audio event deliberately cannot promote an awaiting-resume output. This limitation already existed for optional Pocket/Kokoro, but removing the receipt-capable Apple default makes it the ordinary production path. The replacement fake implements exactly the missing capability and masks this gap. Supply truthful fresh playback proof from the allowed production backings through the existing owner; do not clear the flag merely because `play()` was requested. Verify the same pause/backchannel/resume flow with an allowed engine or authored PCM using the actual player.

2. **P2 — Catch-up can retry/use a failed selected voice without an explicit retry.** `Sources/NextNotes/Agent/Speech/LongFormRenderer.swift:429,446,459`; `Sources/NextNotes/Agent/Speech/PocketAgentVoice.swift:113,119`; `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:681`. After a Pocket playback failure, the synthesizer is `.failed` even though the model owner remains ready. A scheduled Catch-up ignores that availability and still synthesizes an audio artifact. After a load failure, its direct `prepare()` clears the owner's error and automatically tries initialization again; `frames()` can then call preparation again after a failed attempt. Kokoro's `wav()` likewise implicitly prepares. These calls share the existing load task, but bypass the new failed-until-retry policy. Gate the file-render adapter on the selected owner's policy and leave the existing Catch-up text/status when failed. If waiting for an already-owned first preparation is intended for file rendering, distinguish joining that task from starting an automatic retry.

3. **P2 — The committed Settings consumer cannot recover the new failure latch and still advertises Apple.** `Sources/NextNotes/UI/Settings/ModelsSettingsTab.swift:782,918,976`; `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:108,134`. The UI branch is currently pinned at `0fe557a539feed4d4ac088109b128ca36ac03c02`; its committed voice screen is the same legacy screen. After a synthesis/playback failure, clicking the ready Pocket choice or Preview never calls `prepareSelectedVoice()`, so `selectedVoiceFailed` remains true and Preview silently produces text-only settlement while the screen says ready. Switching to a ready Kokoro choice also inherits the global failure latch. Selecting an unready different engine stores the choice only after success, so answers meanwhile continue using the previous ready engine. The macOS tile writes `apple`, which the new setter normalizes to Pocket. This is an explicit integration prerequisite, not a request for the backend agent to take over the UI. Store the requested engine immediately, observe synthesizer availability, and route retry through its API before accepting the Settings integration.

4. **P2 — Automatic startup preparation has no resource admission.** `Sources/NextNotes/NextNotesApp.swift:591`; `Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:128`; `Sources/NextNotes/Agent/Speech/PocketAgentVoice.swift:120,132,136`. On a cold normal launch under warning/critical pressure or concurrent ASR/meeting work, the new default unconditionally starts initialization and a native warm prediction. `Task { @MainActor ... }` removes the await from launch, but does not itself supply pressure/compute admission or establish that native loading is off the main executor. The source call chain contains no existing optional-work admission check or checkpoint. Compare `Sources/NextNotes/Core/Compute/ModelResidencyPolicy.swift:43` (`allowsOptionalWork`) and the existing speculative-load policy. The prior opt-in Pocket path had the same weakness; making Pocket the default and eagerly starting it expands exposure to fresh launches. Preserve automatic download intent while admitting speculative native allocation/warmup through existing resource policy, rechecking after waits. Keep this off the interactive reply/microphone path. No freeze or measured memory regression is established by this read-only review.

5. **P2 — The no-Apple census is too narrow to protect the stated invariant.** `Sources/NextNotes/Agent/Speech/AgentVoicePolicySelfTest.swift:14,18,21,25`; `Tests/Reports/no-apple/check-sink.py:6,8,12`. Both scanners inspect only Swift files under Sources/Tools and three literal names. Adding a `NSSpeechSynthesizer` implementation, a script/Makefile `/usr/bin/say` route, or any synthesis inside the entirely exempt ModelsSettingsTab still yields zero forbidden hits. Renaming only the backing does not hide a literal `AVSpeechSynthesizer` constructor, but the backend-name check itself contributes no robust protection; a different Apple API bypasses it. `AVSpeechUtterance`, `NSSpeechSynthesizer`, executable `say`, selector engine values and script routes are untested. Constrain exceptions to the specific permitted catalog/benchmark operations, scan the relevant complete tree, and retain actual route/backing counters. The current source census finds no shipping sink, but its green marker cannot prove future completeness.

6. **P2 — Part of the migrated receipt proof tests the fake's rejection logic, not the retained native producer.** `Sources/NextNotes/Agent/Speech/PCMReceiptSpeechBacking.swift:65,84,96`; `Sources/NextNotes/Agent/Duplex/PCMReceiptOwnerSelfTest.swift:60,68,74,116`; both deprecated Apple test wrappers at `:7`. For example, a stale played packet is rejected inside the fake before reaching the synth; the assertion still passes if the corresponding native phase filter is removed. Completion during pause is suppressed by the fake itself. Cursor advancement/frame continuity and the nonzero PCM assertion check metadata/sample constants constructed by that same fake. Both formerly distinct Apple owner/timeline flags now execute the identical 53-check routine. This preserves useful actual capture/audio/shadow token and receipt-consumer tests, but loses native callback provenance, real cursor/checkpoint derivation, callback-thread barriers, player drain, and the distinct timeline-producer regression. `PreparedPCMSpeechBacking` retains that producer but is uninstantiated and untested here. Keep the explicitly simulated markers; add coverage that exercises the retained player/producer or exposes malformed/stale receipts at the real receiving boundary, rather than counting duplicate aliases as independent coverage.

7. **P3 — The duplicate store prerequisite is semantically identical, not byte-identical.** `Sources/NextNotes/Agent/Tasks/AgentTaskStore.swift:202`. Diffed commit `5f9a538b` against shared `20d8f9b8`: the signature and all seven executable method lines match; only the two documentation lines differ. Both insert ten lines at the same location into the same original blob `c2a8da69`. Applying both independently creates a same-location insertion conflict; an ordinary three-way merge needs the comment difference resolved and exactly one method retained. There is no behavioral reason to keep two implementations. Prefer the shared prerequisite once and drop/reconcile this duplicate hunk; do not weaken `TaskAuthoritySelfTest`.

8. **P2 — Peer integration has a concrete removed-symbol compile conflict.** `claude2/voice-ack:Sources/NextNotes/Agent/Speech/AgentSpeechSynthesizer.swift:99`; same location on `claude2/voice-mini`. Both peers add `appleSynthesisCallsForTesting` backed by the deleted `AVSpeechBacking.synthesisCallsForTesting`. Their consumers remain in `VoiceAcknowledgementSelfTest.swift:22,137`, Mini's `VoiceDiagnosticSpeech.swift:41,49`, and `VoiceCapabilityConversationSelfTest.swift:752,1492`. Combining those changes with sink removal leaves an unresolved symbol. Replace the diagnostic contract with meaningful selected-route/forbidden-call proof and update the consumers together; restoring the sink or returning a constant zero would undo the policy or make assertions vacuous.

## Checked contracts and limits

**Selection, settlement and approvals.** `AgentSpeechSynthesizer.swift:335` selects only ready Pocket or ready supported Kokoro; the macOS 26.4–26.5 exclusion remains in `KokoroAgentVoice.swift:15`. Legacy/missing/invalid engine values normalize to Pocket; valid Kokoro survives and the legacy identifier has no synthesis reader. Failure sets availability before interrupting the current/queued clauses, preserves completed receipts, stops the backing and fences stale callbacks. Later streamed text remains in the ordinary text consumer; playback does not restart. Tests exercise real delivery/message binding with fakes. `OutputScheduler.swift:467,500` retains unavailable queued updates for explicit re-enqueue instead of automatic recovery playback. Unavailable/failed spoken approval cases retain proposals, record no onset and fire zero effects in the retained evidence; only actual current prompt playback earns the spoken-yes contract. Visual review remains available. No contrary approval route was found.

**First launch and other notices.** Launch preparation follows diagnostic isolation returns, and Pocket callers join its single `prepareTask`/manager. There is no second downloader in this change. Pocket cancellation snapshots and joins preparation and reply producers at quit (`PocketAgentVoice.swift:74–91`, `NextNotesApp.swift:10363,10420`). The launch Task itself is unretained, but late Pocket admission is closed by `terminationRequested`. Kokoro still lacks an equivalent owned preparation termination/join; this is inherited, not evidence for the Settings SIGSEGV. Tests force ModelHub offline for these preparations; no network execution was performed by this reviewer. Fresh absent assets become preparing, then failed on offline/download error. Reply feed/Island show the approved plain availability line; numeric progress remains nil. The committed Settings screen exposes raw model errors and lacks the proper retry contract in finding 3. Reminders preserve notifications/Island text and use the shared sessionless selector (`AgentScheduler.swift:1425–1432`); meeting notices remain notification text/alert sounds. Catch-up preserves text and its audio-absence progress through task completion, subject to finding 2.

**Availability consumers.** `AgentVoiceAvailability` exposes `.ready`, `.preparing(progress: Double?)`, `.needsDownload`, `.failed` and `message`; failure wins over readiness. `AgentSpeechSynthesizer.shared.availability` is the live selected state, while `outputAvailability` is a reply snapshot. Agent feed stores the snapshot in `VoiceSpeechDelivery.availabilityMessage`, which appropriately preserves the historical reason. Island reads the global last-output snapshot (`IslandView.swift:488`), so a later non-speaking Island notice can inherit the prior reply's line; it is not a live preparation indicator. Settings reads model-owner `isReady` instead of this API and can report stale readiness after a playback failure.

**Settings API handoff.** Required shared symbols are `Settings.shared.agentVoiceEngine` (Pocket/Kokoro), `agentPocketVoice`, `normalizedAgentVoiceEngine`/`initialAgentVoiceEngine`, `AgentSpeechSynthesizer.shared.availability`, `prepareSelectedVoice() async`, `canSpeak`, `speak`/`stop`, and the four availability cases/`message`. `outputAvailability` describes a particular reply, not current download progress. Pocket/Kokoro owners retain `isReady`, `isPreparing`, `errorMessage`, `prepare()` and Kokoro OS support/message. `agentVoiceIdentifier` remains a compatibility shim. The current UI ref has no committed consumer of the new availability/preparation API, retains the Apple tile/catalog, waits to save selections, and uses a readiness-only preview gate. A later uncommitted Sonnet screen was not inferred from this stale ref or accepted as reviewed.

**RED/GREEN fidelity.** `producer-probe.py:9–18` extracts nine actual bodies and removes logger privacy annotations; this is more faithful than manually rewritten selector methods. However `availability`, selected engine, initializer, backings, policy splitting and audio settlement are substitutes (`:35–59`), with supported OS hardcoded. The retained red/fixed Swift files are compiled directly by `run-checks.py:47–52`; the driver does not regenerate or compare them to current production. Thus surrounding-state bugs and later source drift can pass. Native TTS/delivery tests mitigate this for the actual selector and partial/unheard receipts, but do not establish the first-launch download, production resume capability or resource admission. Reported RED 9/1 failures and GREEN zero failures are credible within these declared substitutions.

**Settings crash.** Retained final Settings exit is `-11` despite `SETTINGS_OK`; wrapper exit is 1 and the report correctly treats Settings as failed. `settings-crash-metadata.json` locates `objc_release` during MainActor-job autorelease drainage, not an Apple voice/model frame. These component controls argue against those proposed causes, but are not a full original-app baseline. No evidence attributes SIGSEGV to this voice removal, and no crash fix/pass is established. Reports of other branches crashing are corroborative context, not causal proof reviewed here.
