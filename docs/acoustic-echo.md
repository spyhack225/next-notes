# Acoustic echo measurement (2026-09-14)

The 08:31 Agent log showed Next's spoken reply returning through SpeechAnalyzer as a new user turn. The 0.2.17 transcript filter reduced simple reflections but missed short two-word fragments and later revisions of SpeechAnalyzer's cumulative transcript. The 09:06–09:07 log still shows a reply fragment becoming a turn and the whole earlier conversation being submitted again. Version 0.2.19 adds those cases to the duplex and realtime self-tests and corrects the transcript boundary. None of this cancels speaker sound in the microphone signal; VAD still sees speaker energy.

Apple's [voice-processing audio engine](https://developer.apple.com/videos/play/wwdc2019/510/) provides acoustic echo cancellation when enabled on an I/O node while the engine is stopped. It switches both I/O nodes. [AVSpeechSynthesizer can render PCM buffers](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write%28_%3Atobuffercallback%3A%29), so routing all voices through one managed graph is technically possible, but must be measured before changing the shared microphone engine.

On a MacBook Air (Mac15,12), macOS 26.5.2, default built-in microphone and built-in speakers, a 5.53-second spoken sample at 48 kHz and mixer gain 0.65 gave:

| Condition | Mic room baseline RMS | Mic during playback RMS | Result |
| --- | ---: | ---: | --- |
| Untreated input, same graph playback | 0.00143 | 0.02018 | Speaker bleed about 23 dB over baseline |
| Voice-processing input, same graph playback | — | — | `AVAudioEngine.start()` failed, Core Audio `-10875` |
| Voice-processing input, separate output engine | 0.00021 | 0.00068 | Mic playback excess 29.8 dB below untreated input |

This first run disabled voice-processing automatic gain control. Repeating with Apple's default gain control still failed to start the same graph; untreated mic RMS was 0.00167 at baseline and 0.01473 during playback, while separate-output voice processing measured 0.00042 and 0.00168 (19.1 dB lower playback excess). The different gain-control setting and room conditions make the two attenuation numbers unsuitable as a performance benchmark.

The attenuation is **not proven AEC**. Voice processing may also change output gain, noise suppression, or device routing; the probe does not independently measure the acoustic speaker level. Its separate output engine approximates, but does not use, the current Apple/Pocket/Kokoro playback backends. The same-graph failure occurred after `setVoiceProcessingEnabled(true)` succeeded. Core Audio logged an aggregate-device channel-layout failure (`Input: index 1 >= originalLayout size 1`). This makes an unconditional switch to voice processing unsafe on the current machine. The probe's first revision also crashed because its tap closure inherited `MainActor`; the callback is now formed in a `nonisolated` function, and the user's crash report matches that test-only defect.

Rechecked after the macOS 27 upgrade on September 14 with the same spoken sample: untreated playback again reached the microphone (RMS 0.04188 against 0.00144 baseline). Voice processing in the shared input/output graph still failed to start with Core Audio `-10875`. Separate-output voice processing measured 0.00036 during playback against 0.00038 baseline, but the probe did not measure physical speaker level or a person interrupting. That near-zero excess cannot be interpreted as 92 dB of verified echo cancellation. The OS upgrade did not establish a safe AEC configuration for the shipping audio graph.

The repeatable probe is `--selftest-acoustic-measure <audio-file>`. Launch it through LaunchServices to use the app's microphone grant. It fails if the input delivers no frames or untreated playback is not detectably above baseline; it reports voice-processing setup errors separately from the valid untreated measurement.

```bash
say -v Samantha -o /tmp/nextnotes-acoustic-probe.aiff \
  'Next Notes found the file. I can open it for you now. Please tell me if you want another action.'
afconvert /tmp/nextnotes-acoustic-probe.aiff /tmp/nextnotes-acoustic-probe-48k.wav \
  -f WAVE -d LEF32@48000 -c 1
open -n -a 'Next Notes' --args --selftest-acoustic-measure \
  /tmp/nextnotes-acoustic-probe-48k.wav --selftest-out /tmp/nextnotes-acoustic-measure.txt
```

Before calling the Agent acoustically full duplex, measure physical output gain in each condition, test actual Apple/Pocket/Kokoro playback, test a person interrupting while the speaker plays, and repeat across built-in, external, and Bluetooth devices. If the managed graph can start reliably and preserve audible output, route TTS PCM through it and use processed mic samples for Agent VAD/ASR while keeping dictation and meeting capture behavior unchanged.

## Local SpeexDSP playback-reference path (September 14)

The Agent now routes Apple speech's `AVSpeechSynthesizer.write` PCM, Pocket's streamed PCM, and Kokoro's decoded WAV PCM through output `AVAudioPlayerNode` engines. A tap on each output mixer sends copied **rendered** samples, including the selected output gain, to a vendored BSD-licensed Xiph SpeexDSP acoustic echo canceller. Only the Agent's capture callback passes its microphone samples through the canceller before VAD, Apple SpeechAnalyzer, and local end-of-utterance detection. The shared hub's dictation, wake, and meeting subscribers continue to receive their existing input stream. Apple's VoiceProcessingIO experiment above remains diagnostic and is not enabled in this path.

Two self-tests use spoken WAV files for the far speaker and the overlapping near speaker, add a delayed three-tap simulated room response, and fail unless echo-only ERLE reaches 15 dB and the near voice keeps at least 0.7 correlation and 0.45 gain. The revised Speex preprocessor enables residual echo gains with only mild ordinary noise suppression and no automatic gain control. The actual production processor passed `--selftest-acoustic-speech /tmp/nextnotes-far.wav /tmp/nextnotes-near.wav`: **16.5 dB ERLE, 0.87 near correlation, 0.74 near gain**. A simpler tone replay also passed, but the spoken test caught a configuration that had seemed fine on tones. This is digital replay, not acoustic proof in a room.

`--selftest-acoustic-int16 /tmp/nextnotes-far.wav` feeds actual 16 kHz signed 16-bit microphone buffers through the format-conversion branch and checks output format, all 80,000 samples, and at least 10 dB echo reduction. The installed build's regression passed at **11.0 dB ERLE** over **80,000** converted samples. It guards against a previous same-rate format bypass that let Apple SpeechAnalyzer consume untreated microphone samples.

`--selftest-acoustic-live [selected|apple|pocket|kokoro]` runs through the signed app's microphone permission. It requires measurable raw speaker bleed, delivered microphone frames, rendered PCM reference frames, a voice start and completion, and at least 10 dB reduction of the microphone's playback excess. A silent tap or headphones fail rather than producing a misleading cancellation figure. On built-in microphone and speakers, the installed Apple path initially measured **13.0 dB** attenuation (`/tmp/nextnotes-acoustic-live9.txt`), and selected Pocket **11.3 dB** (`/tmp/nextnotes-acoustic-selected10.txt`). An unconditional raw-mic warmup to preserve cold double-talk caused Apple to regress to **4.7 dB** whole-playback attenuation (`/tmp/nextnotes-acoustic-live16.txt`); we replaced it with a bounded rendered-reference coherence check. The revised signed build passed Apple at baseline/raw/clean RMS **0.00264/0.01985/0.00573**, **11.8 dB** attenuation (`/tmp/nextnotes-acoustic-live17.txt`), and selected Pocket at **0.00140/0.01649/0.00522**, **10.3 dB** (`/tmp/nextnotes-acoustic-selected17.txt`). Both delivered **168,000** actual rendered-reference frames. These are individual excess-RMS comparisons, not statistical performance estimates or proof that a person could interrupt cleanly. Kokoro and other devices have not passed this hardware gate.

After an utterance drains or is interrupted, the player and its output engine stop, then the AEC retains rendered reference and its learned room filter for at most 350 ms of microphone input. This bounds the post-stop speaker/room reflection instead of letting the always-running output mixer deliver zero frames indefinitely. A new session or route reset clears adaptation. During a cold first reply, the processor feeds Speex continuously and compares a bounded 40 ms microphone window with rendered PCM over plausible speaker/room delays. Strongly coherent echo uses cleaned PCM immediately; independent near speech keeps the equally delayed raw microphone until the filter matures over its first two seconds. A first-second far-only spoken replay passed **10.7 dB ERLE** and the independent first-100-ms near replay retained **0.89 correlation and 0.89 gain**. Unmatched device routes and first-window speaker bleed remain possible, so transcript echo protection remains necessary.

The spoken post-stop self-test compares actual far/near WAV with the wrapper's fixed two-frame (20 ms) audio delay and requires 10 dB residual-tail reduction plus at least 0.7 correlation and 0.45 gain for the distinct near speaker. The production Swift processor passed with **38.2 dB ERLE, 0.94 near correlation, and 0.89 gain**. The first-100-ms independent spoken near fixture passed at **0.89 correlation and 0.89 gain** through the cold raw-preservation path. A separate sustained sine-wave stop stress probe has measured only **6.0 dB** tail reduction and remains a failing diagnostic. The equivalent vendored Speex C replay reproduced 6.04 dB with playback/capture plus spectral postfilter; its linear AEC output without the postfilter achieved 12.37 dB on the same exactly aligned interval. The abrupt tone-stop transient originates in the spectral stage, not missing reference frames. We leave that bounded failure visible rather than changing the production filter on a tone-only result. There is still no physical near-person double-talk measurement. Measure an actual person interrupting real playback, Kokoro, and external/Bluetooth routes before describing the experience as reliable acoustic full duplex.
