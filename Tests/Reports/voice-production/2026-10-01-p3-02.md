# P3-02: worker progress during conversational input

Status: in progress; new installed producer regression passes, existing conversation-fixture integration under verification.

Confirmed source cause: the background voice worker calls `waitForVoiceInput()` before planning, after model completion, and before calls. Its coordinator wait applies to unclassified input even for reads. The coordinator also clears the answer route's input barrier only when the whole answer stream ends. The final action authority already has the correct post-approval validity seam; it must remain there.

The initial regression uses a real `RealtimeAgent` voice worker and scripted provider, production planner/runner, real approval card and final validity checks. The new executor seam replaces only the external effect after final argument validation. It does not bypass permission or review. A partial answer envelope parks the frontend while a completed read round should lead into another planner round. A complete answer route then leaves its stream tail parked to pin early route release. Approval of the old key occurs while a correction envelope is partial; the old effect must not fire and the existing objective must replan to the corrected key. No microphone, downloaded model, external keypress, user-store seeding, or runtime selection changes are involved.

Additional discovered contract: an old call invalidated at the final gate produces a cancelled runner step. The loop must recheck current owner/revision after the step before interpreting a terminal disposition; otherwise it stops the objective instead of replanning against the correction.

Typed wait behavior, round/read/ceiling budgets, revision refill, the permission broker, ActionRuntime and tool authority are outside the behavior changes.

Root installed results are recorded below. This bounded task does not complete the phase or unblock downstream iMessage hosting.

## Producers changed

- All six actual ToolLoop input waits now preserve foreground/typed semantics while skipping voice-worker planning and read paths.
- Coordinator wait clients use one continuation dictionary. Read clients wait only on pending input; consequential effects also wait on a failed-input hold. Input/hold setters resume only eligible clients; cancellation removes and resumes its exact client; close/discard clear both causes. Failure sets the hold before releasing input, so a wake-up cannot briefly admit an unclassified effect.
- A parsed answer route resolves its current epoch while its generation tail continues. A complete control envelope stops consuming its stream and applies the existing revision/cancel/new-work action before releasing the effect barrier. Partial envelopes retain the barrier.
- ToolStepRunner binds an initial revision for explicit-memory and whole-turn callers, then preserves the existing per-round replacement. Final validity checks owner/revision before waiting and afterward. A cancelled stale proposal is skipped without charging repairs or stopping the corrected objective; the round loop rechecks revision before interpreting its result.
- Direct shortcuts also pass final risk/owner/revision validity. A two-step app+URL shortcut checks the original revision before starting its second action. A stale Apple whole-turn result falls through to the existing round planner with the same provider, runner and budget; current native turns retain their path.

No approval or effect wait was added to model/read budget charges. Typed 50 ms wait behavior, refill intervals, limits, provider selection, user settings and ActionRuntime were preserved.
