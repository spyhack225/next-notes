## Contract and producer scope

One `Agent/Duplex/VoiceContracts.swift` defines the process-monotonic `TurnID` and `OutputID`, string-preserving `TaskID`, replay-relative `VoiceSessionInstant`, voice events/commands/state, and the future single-ledger task value contracts. Existing latency `VoiceInstant` is unchanged. `TaskOrigin.remote` reuses `ActionOriginContext`; no mutable TaskRecord mirror, store or queue is created.

The reducer is pure: no clock, singleton, Task, permission, I/O or playback execution. Failed response input is removed so reads/planning resume, but a distinct failed-input hold preserves consequential writes. Stale decisions/end/discard/commit events cannot release newer input or that hold. Later current classification, synchronous current withdrawal and close release it. Duplicate commitments start exactly one response, including duplicates after completion. Duplicate output start preserves lifecycle; a distinct start cannot silently overwrite a current output. Session close preserves work and only explicit cancellation commands cancel tasks.

`VoiceSession` is a shadow observer. Every command is diagnostic only; no new timers execute. Existing capture ticks supply timer facts. Ordered events are synchronous and may be recorded explicitly; comparisons coalesce after the current producer stack settles, adding no await to the turn path. Retained command and mismatch samples are capped at 200; a separate total divergence counter does not hide failures beyond that cap. Live logs are bounded.

Additive producer hooks preserve all legacy work, acoustic, approval and playback behavior:

- Capture emits open/close, activity, partial, acoustic discard, hesitation and commit identities. The captured TurnID travels through both continuing and one-shot handle branches. Current `discardInput` emits global withdrawal synchronously, distinct from stale acoustic discard.
- Coordinator maps its epochs and actual response UUID explicitly to TurnID, records route facts at existing classification seams and response completion after the real producer settles. Existing jobs carry factual origin-session metadata solely to identify session-owned approvals, and existing job transitions supply accepted/completed/cancelled observations.
- RealtimeAgent's frontend owner generation carries an optional observation identity, independent of shared `isThinking`. Tracker/audio start hooks carry the response identity.
- Audio maps the real synthesizer generation to one OutputID. A tiny read-only synthesizer lifecycle snapshot exposes clause presence/rendered/paused facts without text. A settled callback runs after actual clause clearing/queue advance. The streamed-reply open/finalized fact distinguishes an inter-clause generation gap from whole-output completion. These facts observe, never control, playback.
- PermissionGate observes factual session-owned present/respond/cancel transitions after review and pending state changes. Authority, broker, grants, blockers, actual approvals and foreign ActionRuntime remain unchanged. Root owns separately integrated durable Gate journal hooks.

## Independent comparisons and coverage limits

Effects compare the actual coordinator pending input or failure hold. Pending-turn comparison uses current frontend/queued request identity and matching reply-output identity, not `isThinking`. Output compares matching generation plus queued/playing/paused/heard lifecycle, not `isSpeaking` alone.

Floor reference uses established acoustic/lexical capture facts and real `voiceInputActive`. A held filler survives acoustic reset through existing Capture `lastEmittedRequest`, gated by actual active session and pending input. This avoids reading an old `um` from conversation history while a newer meaningful request is already queued. Bare direct coordinator fixtures without an independent capture/control floor source report unavailable floor samples separately; they do not earn an all-field zero-divergence claim. No comparator mismatch is whitelisted.

The installed integration fixture is `@MainActor VoiceSessionReducerSelfTest.run(tracePath:) async -> Bool`, registered by root. It runs ten pure traces, existing actual capture correction flow through real approval/final validity, an actual captured filler followed by current withdrawal/close, a newer meaningful queued commit observed before history update, and actual streamed output:
queued before first render → backend first acknowledgement → completed first clause before finalize → second clause in the same generation → finalize/final completion. It requires matching independent queued-clause evidence, all four capture comparison fields, zero unavailable capture fields and zero total divergences. It uses scripted frontend/model fixtures and a recording output backing, not owner data, microphone or live model.
