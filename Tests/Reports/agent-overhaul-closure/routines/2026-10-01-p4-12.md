# P4-12 routine model and output producer changes

The existing `ScheduledRunner` chose only the library model or OpenRouter; Apple Intelligence was invisible to the router. `LiveScheduledRunEnvironment` then constructed a bare `LlamaLLMProvider` and always requested 384 output tokens. `AgentScheduler.deliverRoutineResult` held every result in quiet hours, including the exact time the owner deliberately chose for a routine.

The change keeps the existing runner, schedule store, task recorder and delivery path. Auto chooses a runnable library model, Apple Intelligence, then cloud; during recording it chooses configured cloud before Apple and never starts the library model. Explicit local can use Apple when the library model cannot run. Explicit cloud remains cloud. Apple tasks record `backend: apple`, and their graph reader is local `.appleFoundation`, preserving graph consent at the actual reader boundary.

The live library model uses the selected Agent role when it is an app-local provider, otherwise the existing app-local factory. An optional stored `maxOutputTokens` retains legacy decoding. Legacy and newly created digest/podcast schedules request 1,536/4,096 tokens respectively; other schedules request 384. The live producer clamps those requests to the provider window (`min(requested, max(384, contextTokens / 3))`, with invalid nonpositive requests bounded to one). A routine deliberately scheduled inside quiet hours shows its result then and remains silent; a late outside-hours result or a trigger result waits.

## Recipe clarification

P4-12 Target 1 requires unavailable-Apple/cloud suffixes in skip reasons, while its red-first paragraph asks every old router answer to remain unchanged with Apple unavailable. The implementation preserves each original routing decision and base cause, then adds the Target 1 plain-language suffix. Existing expected skip strings therefore change, without changing the decision class, permission rules, time/tool budgets, or score thresholds.

The existing three-sentence prompt limit and Hermes text planning on Apple are separate P4-06/P1-05 contracts. This change neither removes that sentence cap nor claims native Apple tool behavior from routing fixtures. It also does not establish scheduled crash recovery, leases or receipts.
