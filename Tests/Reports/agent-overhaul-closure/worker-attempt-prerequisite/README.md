[Original evidence](original-installed-evidence-manifest.json), [extended original evidence](original-extended-installed-evidence-manifest.json) and [current installed evidence](current-app19-evidence-manifest.json) retain exact logs, source snapshots and hashes.

The cause was not an absent helper type: actual Manager execution created attempt-zero work, attributed late facts by task ID alone, and ignored primary tool-start/terminal write rejection. Completed or thrown effects retain Runtime receipt behavior while rejected completion history is reported without task success.

This verified prerequisite does not implement or complete P6-05 heartbeat, complete parent P6-06, create retry/task-receipt joins or unblock IM-16. The latest actual aggregate is app13's fixed quick **FAILED 3/10**, with the bar unchanged 9/10. That is historical app13 evidence, not an app19 model verdict. ## Implemented responsible-producer scope

1. **Existing primary commit condition.** Add a small optional condition value or narrow parameters to existing `AgentTaskStore.save` → `TaskStore.commitAuthoritative`. In the existing `BEGIN IMMEDIATE`, decode/validate the targeted current row and compare exact expected task ID, stored attempt, leaseOwner and legal pre-state. Start accepts only queued and its previous durability attempt (nil is legacy0); positive attempt must advance exactly once, with overflow rejected. Ordinary independent non-attempt mutations remain explicit; no second store/ledger, snapshot merge, retry or silent reload is added. Test mismatch by calling the actual transaction, not only its predicate helper. Fresh expected file/generation checks already refuse other-instance writes; preserve them.
2. **Bounded typed local worker start.** For actual typed (`user`/`text`/`selftest`, no schedule, local backend) dispatch, set attempt = prior +1, leaseOwner = current process pid, attemptStartedAt = now and runtimeClass localDeterministic, keeping neverAuto and existing receipt/parent fields. Commit running plus workerStarted at that same attempt under the queued precondition, then capture the exact immutable task/context. No observer-derived attempt and no metadata-only success. Keep ACP/voice/scheduled/unknown ownership out of this first claim; their producers need separate verified admission, not inferred coverage.
3. **All captured worker writes.** Thread the expected attempt/owner/pre-state into actual Manager update/persist calls. On each async return/error, refuse stale attempt or illegal terminal replacement before artifact take, success announce/activity, permission/input park or handle cleanup. Successful terminal SQL admission precedes completion projection; SQL failure is visibly storage failure with history kept. A positive SQL commit plus export failure remains accepted. Cancel commits the exact stored attempt before cancelling its task and invalidating approval; failed cancel leaves worker/card/token unchanged. Existing restart stays held, with no dispatch.
4. **Existing pre-effect seam and journal admission.** Add a defaulted bound validity callback on TaskJournalContext and pass it from LocalBackend through the existing Executor `isStillValid`. That final check must use current primary attempt/status authority, not only cached Swift state. Change record to report primary admission; make the actual final bound toolStarted call throw/refuse backing on false. Check its expected attempt/status in the same commit transaction, avoiding a read/check-write race. Existing final validity await is already on the path; no additional sequential await/model pass/timer is justified. Non-task tools still use their original unbound path.
5. **Permissions without new ceremony.** Bound capture rejects wrong attempts; token consumption is pinned to exact queued-to-running attempt/request arguments. Restored approval/input already commits queued before dispatch; that explicit continuation allocates a new attempt, invalidating the old one. Preserve exact pending request/review/provenance. The old worker's needsPermission handler must recognize a matching already parked waiting row without writing an extra unrelated transition. The actual local captured/restored Manager callbacks honor admission failure; broader live PermissionGate.ask/standing-grant ordering is excluded and remains unchanged. No generic question or directory expansion.

A Bool validity hook alone is insufficient: actual toolStarted SQL failure must prevent backing, and the commit must compare against primary state transactionally. Completion rejection is propagated after Runtime receipt handling on both returned and thrown paths; no task success is emitted. The separate receipt store's actual `.fired` disk proof is already bounded P6-06a; this task must not claim a new cross-store atomic transaction, task receipt join or completed-effect receipt ownership.
