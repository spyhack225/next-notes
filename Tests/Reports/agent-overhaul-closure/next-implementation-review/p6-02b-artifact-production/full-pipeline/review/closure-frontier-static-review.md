1. **Typed capture changes an exact path.** Fixed AgentArtifactLedger.capture(record:) trims record.value before merging. Actual FilesystemExecutor.resolved preserves nonempty input, and read returns URL.path. A valid filename ending in a space therefore produces an exact typed result path but a different trimmed typed ledger value. LocalBackend returns the former; Manager's value-keyed merge appends the latter as another artifact carrying metadata for the wrong location. The old string ledger already had this normalization, so this is an inherited producer contract gap, not a claimed introduced or natively reproduced regression. Preserve exact typed values, checking whitespace-only solely for rejection; the legacy string API can keep its established behavior. Prove it through the same actual Manager→filesystem backing with a harmless temporary trailing-space filename before both versions.
2. **The witness test does not read the witness.** The fixture's assertion named SQL/witness canonical equality compares retained SQL rows to another SQL load and checks freshManager.historyReadFailure. The actual marked AgentTaskStore.load chooses SQL before payload decoding; check() decodes only TaskHistoryExportHeader. This establishes SQL equality/header compatibility, but not retained JSON artifact metadata. Add safe temporary export `tasks` extraction and decode with the existing ISO8601 AgentTask codec, then assert exact equality against canonical SQL including approved typed kinds/titles/order. Source encoding appears consistent; this is a verification gap, not a proven export bug. Standalone legacy AgentTask bytes and the malformed dual-view decode negative do not replace enriched actual export evidence.
