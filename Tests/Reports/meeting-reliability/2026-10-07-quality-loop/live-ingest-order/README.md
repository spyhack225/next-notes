# Live meeting ingest order: original evidence and bounded producer repair

The original source drops an out-of-order track result from immediate live context. `MeetingSession.add` sorts its accumulated transcript, but `MeetingContextStore.ingest` treats array count as an append cursor. Inserting a newly completed earlier segment shifts the old tail; the suffix selects an already-seen row and the new source is omitted before bus delivery. When the bus later recovers the segment, `noteIngest` appends its earlier speech to the evidence buffer's newest end. This violates the reader's chronological selection contract.

The reviewed producer patch passes the exact incoming final through the existing ingest seam, reuses source-aware deduplication for every supplied batch, and inserts unique speech chronologically in the existing bounded 360-row evidence buffer. It adds no store, queue, model call, timer or await. Session bus publication remains the same existing Task. Only the bounded buffer is searched, not the full meeting history. Cross-track evidence remains distinct and retains its original authority.

## Provenance and limits

The component compiles the whole actual `MeetingContextStore`, `MeetingContextExtractor` and context model, exact `Session.add` / `insertSegment` bodies in an adapter, and exact cadence/reader/prompt bodies. It calls `add` twice before the first await to observe the omission before publication. Existing publication Tasks record events in a substituted bus; those events are then delivered deterministically to the actual `ingestFinal` consumer. The maintained cases use the same real isolated context save/readback logic and a substituted empty completer.

Capture, wake interpretation, app controller, MeetingStore backing, runtime/model provider and async bus transport are explicit boundaries. This is not native full-Session/capture proof, real bus scheduling/subscription proof, production MeetingStore proof, ASR/voice performance proof, or semantic model recall proof. Authored public speech is the only fixture payload. No owner meeting speech or raw model outputs are included.

`post-session-clock-latest-end` checks the authored late old-row ordering scenario. The broader overlapping-segment maximum-end clock proposal is excluded from both source variants and maintained acceptance. This ingest repair cannot explain or fix the independently observed future-action semantic miss when all relevant model input is already visible.
