# Official provider identity routes — verified 13 October 2026

This table concerns Next Notes recording alongside an existing macOS meeting client. An embedded app, a meeting bot, a provider transcript and a native process tap have different access contracts. No account, grant, cloud action or physical provider observation was attempted. Published update dates are retained where shown; an undated page is marked with the verification date, not an invented release date.

| Route | Participant identity and speech evidence | Access and realistic use |
| --- | --- | --- |
| Existing Apple/Google calendar | Invite display name or address; title/time/link. No attendance or voice binding. | Existing EventKit/Google calendar connection; current GoogleOAuthClient requests only calendar.readonly. Useful preparation and manual choices without a new provider grant. |
| Google Meet REST participants/sessions | Display names for signed-in, anonymous and phone participants; signed-in provider IDs; distinct device/rejoin sessions. Includes Companion/viewer/room endpoints. | Meeting-space owner or participant authorization. Participant method requires meetings.space.readonly or meetings.space.created. Connected status is not speaking. People/profile/email availability is separate. [Participant guide](https://developers.google.com/workspace/meet/api/guides/participants), [method/scopes](https://developers.google.com/workspace/meet/api/reference/rest/v2/conferenceRecords.participants/list) (method updated 2026-09-14). |
| Google Meet structured transcript | Participant reference plus speech start/end/text; strongest small post-call route when available. | Same method-specific Meet scopes; artifact must have been enabled before the call ended. Entries expire after 30 days; transcript does not require a recording. API entries can differ from edited/interleaved Docs text. [Entries](https://developers.google.com/workspace/meet/api/reference/rest/v2/conferenceRecords.transcripts.entries) (2025-04-02), [list/scopes](https://developers.google.com/workspace/meet/api/reference/rest/v2/conferenceRecords.transcripts.entries/list) (2026-09-14), [artifacts](https://developers.google.com/workspace/meet/api/guides/artifacts). |
| Google Meet Media API | Its own WebRTC source-to-participant/session evidence; not a stock-browser audio-tap metadata hook. | Preview currently accepts no new signups. Restricted media scope, eligible meeting and app, host/admin controls and participant access rules. Not a default implementation commitment. [Get started](https://developers.google.com/workspace/meet/media-api/guides/get-started) (2026-10-01), [media overview](https://developers.google.com/workspace/meet/media-api/guides/overview). |
| Zoom Apps SDK | Roster and active-speaker events inside a registered embedded Zoom App. Optional email-by-consent. | Roster/all-speaker events require host/co-host, no Guest Mode. Email API supports participant role too, but host/co-host/individual consent varies by scenario. Breakout scope is the current room. It is not an external native-app API. [SDK roles/capabilities](https://appssdk.zoom.us/classes/ZoomSdk.ZoomSdk.html) (v0.16.42, checked 2026-10-13). |
| Zoom RTMS | Participant ID/name attached to timed transcript or per-person audio. Merged audio ID zero cannot identify a person. | Developer Pack credits; user-managed General Marketplace app, media scopes and host-controlled access. Transcript-only meeting:read:meeting_transcript is the smallest optional identity stream. REST start additionally requires meeting:update:participant_rtms_app_status and an invitee who has joined. Server clocks and buffered delivery need local alignment. [Overview](https://developers.zoom.us/docs/rtms/meetings/), [app/grants](https://developers.zoom.us/docs/rtms/meetings/add-features/), [host experience](https://developers.zoom.us/docs/rtms/meetings/ux-overview/), [media fields/clocks](https://developers.zoom.us/docs/rtms/meetings/media/) (checked 2026-10-13). |
| Zoom past participants / Meeting SDK | Past roster offers names, presence and sometimes email, not speech intervals. Meeting SDK owns its own embedded client/media. | Past endpoint requires paid Pro-or-higher account and resource-authorized meeting:read:list_past_participants (or admin variant). External email is conditionally disclosed. SDK current policy directs AI notetakers to RTMS; outside-account participation review/ZAK/OBF requirement effective 2026-03-02. Neither route permits arbitrary stock-Zoom voice naming. [Past participants](https://developers.zoom.us/docs/api/meetings/#operation/pastMeetingParticipants), [email rules](https://developers.zoom.us/docs/api/using-zoom-apis/#email-address-display-rules), [SDK policy](https://developers.zoom.us/docs/meeting-sdk/), [macOS admission](https://developers.zoom.us/docs/meeting-sdk/macos/get-started/) (checked 2026-10-13). |
| Teams meeting app/bot metadata | GetParticipant can return name/email/role/inMeeting for a known participant ID. Scheduled join/leave events provide presence, not voiced intervals. | Installed in-meeting app; unknown/blocked app may get 403. SDK requires meeting/participant/tenant IDs; GetParticipant documents roster limit below 350. Join/leave subscriptions need OnlineMeetingParticipant.Read.Chat RSC and bot present before events. Not an external-Mac process API. [Meeting app APIs](https://learn.microsoft.com/en-us/microsoftteams/platform/apps-in-teams-meetings/meeting-apps-apis) (updated 2026-10-13). |
| Teams Graph transcript | Attributed WebVTT voice tags/timestamps; metadataContent example supplies speakerName plus absolute speech times. A separate format deliberately omits speaker information. | Work/school delegated OnlineMeetingTranscript.Read.All or permitted application/RSC route; personal Microsoft unsupported. Application access policies/admin consent apply; .Read.Chat is scheduled private chat, not channel meetings. Ad-hoc content uses separate CallTranscripts.Read.All. Calendar-unassociated create-onlineMeeting and live-event limitations apply. Tenant may disable transcripts or attributed output; respect GraphAccessToTranscriptsDisabled/SpeakerAttributionNotAllowed. Names alone in VTT do not guarantee unique participant/email identity. [List](https://learn.microsoft.com/en-us/graph/api/onlinemeeting-list-transcripts?view=graph-rest-1.0) (2026-06-29), [content/metadata](https://learn.microsoft.com/en-us/graph/api/calltranscript-get?view=graph-rest-1.0) (2026-07-01), [permissions](https://learn.microsoft.com/en-us/graph/permissions-reference). |
| Teams real-time media bots | Active speakers per audio frame versus broader dominant-speaker set. Applies to the bot's own meeting media. | Microsoft does not recommend this platform for meeting AI agents. Specialized app-hosted bots require C#/.NET and production Windows Server/Azure infrastructure, not an external native macOS recorder. No default bot/server architecture proposed. [Real-time concepts](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/real-time-media-concepts) (2026-02-20), [requirements](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/requirements-considerations-application-hosted-media-bots) (2026-07-22). |
| Webex REST | Participant resource for active/ended meeting; transcripts/snippets can expose person name/email and offset/duration. | OAuth meeting:participants_read / meeting:transcripts_read plus actual meeting-resource access. Artifact generation/policy required; Admin snippet access not supported in current reference. Older guide describes a feature toggle; current overview differs, so test actual account admission and timestamp units before promising snippets. No arbitrary-attendee access assumed. [Meetings/scopes](https://developer.webex.com/meeting/docs/meetings), [resource guide](https://developer.webex.com/meeting/docs/api/guides/access-meeting-resources-guide), [transcript reference](https://developer.webex.com/meeting/docs/api/v1/meeting-transcripts), [participants](https://developer.webex.com/docs/api/v1/meeting-participants/list-meeting-participants) (official search excerpts checked 2026-10-13; some direct API pages did not render through browser extractor). |
| Slack Huddles / other stock apps | Physical visible labels or a separately accessible attributed artifact may assist confirmation. | Slack Calls API documents third-party call integration, not a basis to claim native Huddle voice access. No supported universal external identity API was established here for Huddles, FaceTime, WhatsApp or arbitrary clients. Use manual confirmation unless a real supported source is demonstrated. [Calls API contract](https://docs.slack.dev/apis/web-api/using-the-calls-api/) (checked 2026-10-13). This is a research limit, not proof no future interface exists. |

Displayed names are claims supplied by the provider/account/user; they can be changed, duplicated or used by a room/device. Email is optional provider/contact data, never inferred from a name or combined across different people. All provider streams/artifacts need a correct conference occurrence, device/session identity and local recording-clock join before naming a local diarization cluster. A successful API response, roster count or inMeeting flag does not establish that join.

The default still works with local capture, neutral speaker labels and explicit human naming. Provider connections are app-managed, optional, explained in plain language and scoped to the chosen feature. A missing admin/host grant is an honest unavailable capability—not a request to paste keys, a blocker to recording or permission to bypass provider policy.
