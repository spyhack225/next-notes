# Universal meeting audio reliability — pre-implementation roadmap

Status: source-grounded plan, **no implementation or new native/ASR/model test by this agent**. Root owns the signed baseline tests, read-only HAL inventory, actual owner payload/route observations and coordinated execution. Reuses the [capture audit](../../2026-10-13-audit/capture-source/README.md). Current source pins and exact existing-test scopes accompany this plan. No production source, app/default/account/device setting, index or model was changed.

The requirement is device-independent reliability across input/output combinations and changes, not an AirPods-specific branch. “Universal” means every actually exposed supported format/route satisfies one capture/clock/ownership contract, and unavailable hardware is reported honestly; it does not mean a failed external driver, powered-off microphone or OS sleep can be made to supply missing sound. No unsupplied audio may be called complete or recovered. Class coverage and actual endpoint/model/macOS coverage must be recorded separately. An untested USB/virtual/Bluetooth class remains untested, not implicitly supported by a built-in test.

The owner's explicit diagnostic override removes an arbitrary **free-memory percentage admission gate** for this new bounded investigation. Record free/pressure/swap metrics; do not reuse earlier 55% refusal as a current gate or success measure. Root coordinates the exact owned process/time/resource safety profile before each stage; no competing development work, foreign process signals or product capture/full-duplex serialization. This roadmap does not install a global memory ceiling or change the reference-machine ASR/voice speed/quality requirements.

## Matrix and supported capabilities

The 20-row device-route matrix covers built-in, output-only Bluetooth, headset duplex, independent Bluetooth/physical routes, analog jack/headset, USB headset/mono/stereo/multichannel interfaces, independent USB clocks, DACs, display/dock, external speaker, virtual/aggregate/multi-output, continuity/accessory, pro-audio, app-selected output distinct from OS default, and unavailable routes. Every **available** row gets a capability record, stable capture smoke and applicable transitions. Missing devices/driver/account/grant are UNAVAILABLE with exact missing dependency, never passed. The 15-row transition matrix covers input/output selection, automatic duplex mode changes, rate/layout changes, unplug/power/return, app routing, Bluetooth replacement, grant transitions, sleep/wake, overload, lifecycle races, flapping notifications, simultaneous Agent playback, mute/gain/silence and clock discontinuities.

Build cases from observed endpoint capabilities, not guessed transport defaults. Exercise rate families 8/16/24/32/44.1/48/88.2/96/192k only where actually exposed or as extra synthetic converter boundaries. Cover mono/stereo/multichannel, interleaved/planar, supported integer/float encodings and legal buffer sizes, unequal callback sizes, empty/short/large packets, null/invalid ABL, invalid/nonfinite samples, absent format and unrecognized layout. Unsupported formats must fail visibly at their responsible boundary without claiming captured sound; converter availability is measured. Sampling-rate/profile assumptions must not be hardcoded to one brand.

Use independent channel-coded public PCM: left-only, right-only, both distinct, phase-opposed channels, clipped/quiet speech, silence/DC/noise, deliberate pause and overlap. Define the desired mono-channel policy before scoring: preserving source roles matters more than producing any nonzero value. A multichannel microphone may have its useful signal beyond channel 0; an average can cancel phase-opposed signals; the existing raw meter/permission hint reads channel 0. These need producer/consumer checks, not blind max-level or first-channel fixes. Do not mix microphone into system capture to make diarization pass. Native CAF quantizes float to 16-bit; file parity uses expected quantization or exact source-reader parity, not false float-bit equality.

Conference-provider dimension includes available Zoom/native, Google Meet/browser and at least another available native/browser meeting source; pin browser/provider/version and any app-specific input/output selection. Global tap excludes Next Notes' own process but records other played sources, so provider sound/background music/app playback cannot be equated with one remote speaker. Bluetooth/wired isolation and speaker acoustic bleed are separate quality controls. Captured mic source or a roster name is not independently verified voice identity; no route/echo change may grant execution from another person's sound.

## Phase 1 — prove the first incorrect frame/format/clock contract

Use the existing native system capture/convert boundary in a narrowly scoped diagnostic after this plan is reviewed. Do not create a second capture owner or duplicate the product pipeline. Capture compact sums/extrema/event counters, not per-buffer payload logs: tap ASBD and actual aggregate input stream ASBD; ABL buffer count/channels/data bytes; native sampleTime/hostTime validity/deltas; constructed buffer frameLength/format/stride; input offered/consumed count, converter result/status/error/output frames; output packet frame count and native-clock duration. Include first/last timestamps and route/config generation. PCM/wave/reference payloads stay in 0700/0600 diagnostics, never public logs/relay. Inspect supported formats dynamically and validate received bytes against actual per-buffer frame/layout semantics before trusting a wrapper.

This stage must distinguish four locations: native callback already under-delivers; ABL→AVAudioPCMBuffer interpretation changes frame count; converter changes rate/count incorrectly; later delivery/writer/live clock loses or compresses valid output. Compare input frames/input rate, output frames/16000 and independent native clock. Account for measured converter startup delay/rounding/buffered tail rather than guessed wall sleeps. Consistent 0.5 normalized slope is a hard contract failure, not a tolerated performance difference. If any required raw field is missing, return UNKNOWN, not “converter fixed.” No threshold change or brand special-case follows from the old three-second peak test.

Native route case must reproduce the original device/provider configuration, then test an alternate class to falsify a brand-only explanation. Root's read-only hardware inventory is not a replacement for private app IOProc observations. Diagnostic-only instrumentation may extend existing selftest/metrics seams, with production defaults unchanged and no extra model pass, retry or per-callback heavy allocation. Select the smallest responsible producer repair only once the first mismatch is isolated.
