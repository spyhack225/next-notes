Read-only independent audit. No build, model, app, recording/data/source/index edit or owner-payload read. Parent/root owns actual logs/PCM and installation provenance. ## Exact error origin and scope

The exact “No speech detected in audio” string comes from FluidAudio OfflineDiarizationError.noSpeechDetected. The offline segmentation processor throws for no samples; global cluster also throws when timed embeddings are empty. It is **speaker identification**, not proof that ASR/the microphone/full meeting contained no speech. DiarizationService reads only saved CAF systemChannel1, writes the failure to its per-meeting problems/usage, retains transcript, and normally hands off to notes. No transcript or meeting-wide capture erasure follows from that catch. MeetingAudioWriter channel0 is microphone and1 is system.

Automatic MeetingPipeline.shouldDiarize checks settings/audio existence and refuses known saved system loss. Direct identifySpeakers/reidentify calls use the same service but bypass that automatic eligibility test. Hence the reported M3 missing-system count would prevent current automatic diarization; the error must be joined to its actual meeting/run/stage, direct request or earlier metadata before claiming one common incident. Parent performs that join.

## Why the partial label persists

MeetingCaptureIntegrity.hasPartialCapture ORs interruption, captureGap, missingCaptureFrames, audioWriteFailed and missingSavedMic/SystemFrames. Normal Stop/long-window processing cannot clear those facts. Session.reportHealthIssue marks gap for microphoneStalled/systemStalled/systemUnavailable/captureGap. Even a tap startup error that later joins leaves a real/uncertain missing interval marked. The list UI shows the label when not live; .done is independent.

The15-second health check uses latest **received buffer** wall time. MeetingCaptureDrops.observe accepts any nonempty packet, even all-zero samples. Thus regular zero deliveries satisfy health/captured progress without proving audible speech. Without TCC system capture permission the tap can start successfully and emit zeroes; Core code explicitly documents this. Retry30s×at most10 handles errors/timeouts only. It cannot detect a silent denied tap or automatically repair a running tap that later stops delivering. No zero samples alone establish permission denial, since real silence also exists.

Writer progress is cumulative paired saved PCM and can include synthesized padding. lastCapturedAt derived from writer frames is a timeline lower boundary, not per-channel original-speech coverage. Saved loss counters distinguish originals trimmed behind the paired cursor. Missing delivery before a callback, failed conversion returningnil and callbacks yielding to a terminated stream are not all counted by the existing stream-overflow counter. Zero overflow counters therefore are not complete native IO coverage.

## Conditional rate failure explains the observed propagation

Actual writer append uses per-source nextCaptureFrame after the first packet, ignoring every later native captureHostTime-derived startFrame. Its purpose is to avoid turning delivery jitter into padding/trimming. System live transcription similarly establishes first packet origin once, then advances from converted sample counts. This is an implicit continuous correct-rate contract.

If mic delivers16000samples per wall-second but system supplies8000 with correct wall timestamps, the system clock advances at half speed. The writer allows80000frames/five seconds of lead; then it pads the slow side with zeroes to keep microphone saving. Later system packets now lie behind the written cursor and are trimmed, even though their originals still went to live ASR. With this conditional input, expected discarded frames areN/2−80000. Parent's36,603,189-frame CAF yields18,221,594.5 predicted versus18,220,683 observed, difference911.5frames/0.05697s. The implied retained prefix is5.057s and clock drift~1143.85s, close to reported first/last nonzero bins1..6 and system drift up to1136s. This is highly consistent propagation arithmetic, not an executed writer regression or exclusive upstream diagnosis.

Neither a writer-only timestamp change nor lowered speech threshold repairs missing/misinterpreted native frames. Replacing cumulative clocks blindly can introduce jitter-driven gaps. Core SystemAudioCapture creates a stereo global tap, records tap ASBD before aggregate creation, then wraps the aggregate IOProc AudioBufferList using that saved tapFormat. AudioConversion capacity/rate is computed from that buffer.frameLength and buffer.format.sampleRate. The first unverified external boundary is whether the actual aggregate input buffer layout/frame count/rate matches that tap ASBD. Mono/stereo/interleaved/noninterleaved mismatch, changed hardware/aggregate rate, conversion short output, or callback cadence/drop are hypotheses. Existing source does not expose enough native shape/rate observations to choose among them.

## Recovery preserves what survived

FinalTranscriptService refuses to replace live originals on a track with known saved audio loss; parent reports acceptedmictrue/systemfalse, which is consistent with this protection. Preserving live text cannot restore saved waveform or repair a compressed transcript clock. Both live and final use shared RMS0.01 admission, so known below-floor word loss remains separate. Empty live permits an empty final by the word-count acceptance rule; valid empty processing does not mean no speech existed.

A thrown final-pass error is caught globally and keeps live transcript, names transcriptPass live-only:failed, and reports failure if live was empty. A successful final processed before a later channel error is not committed independently. This is a separate fallback/completeness seam, not evidence for the observed system rate loss. Current pipeline runs saved audio recovery for empty-live or dropped live windows even when the optional quality pass is off. Interrupted-recording startup repair marks the retained capture boundary, while processing-only restart retains normal Stop and does not invent a capture interruption.

## Regression and repair order

1. **Native input contract first.** On an explicitly coordinated short physical system-audio route, collect counts at the existing IOProc/conversion seam: tap and actual aggregate input ASBD sample rate/channels/interleaving/bytes-per-frame; AudioBufferList buffer count, channel counts/data bytes; native sampleTime/hostTime deltas; constructed input frameLength and converted mono frames. Aggregate counters/extrema into existing diagnostic/metrics scope, not per-buffer transcript or large log streams. Compare raw native-clock duration with converted samples/16000. Do not alter user defaults, guess a rate, load another model or retry until the first mismatch is proved.
2. **Prove propagation through real consumers.** Reuse actual Session capture injection + actual Writer and live ChunkedTranscriber with bounded authored PCM/fake ASR solely for transport. Baseline full-rate and scheduling-jitter cases preserve exact ordered PCM/time; half-cadence authored source should reproduce cumulative-clock compression/padded system tail/missingSaved frames through actual append/stop/CAF readback. Include source-late join, dropped callback, actual interleaved stereo/mono layouts and nonfinite/zero/quiet controls. These do not prove words. If source format/convert is faulty, fix that producer then require the original native route to provide full rate, exact PCM/clock parity and healthy saved/live boundaries.
3. **Normal-flow word proof.** After rate/shape fix, use both tracks in short then long physical call, normal Stop/drain/same final Task and fresh saved readers. Assert mic/system expected timeline, preserved remote speech and no trimming, correct final acceptance, note facts/participant attribution and responsiveness. Source-half-cadence harness or .done cannot substitute for the owner route. Retain original before/fixed evidence and no special-case meeting content.
4. **Separate secondary seams.** Investigate system Stop callback/drain race: stop enqueues HAL teardown asynchronously; Session finishes its system continuation without awaiting native lifecycle idle, and terminated yields are not counted. Confirm any pre-Stop accepted callback actually lost before adding a join at the existing Stop seam; preserve full duplex. Extend tap tests to healthy-start-then-stall/recovery and successful zero delivery without claiming TCC. Treat dependency noSpeech as track-specific unavailable speaker evidence; never scrub its banner to declare capture fixed. Digital-zero-only diarizer skip/typed outcome is at most a bounded eligibility mitigation after source regression, not a repair of nonzero but clipped remote speech. Native quiet/noise acceptance and per-track final error fallback require their own unchanged original regressions.

Existing reusable flags: meeting tap retry (start errors/late first origin/Stop race), capture converter/buffer regression, audio retention/writer, meeting integrity (sticky loss/restart/save/fresh reader), meeting finals (per-track refusal and live preservation), health, meeting quiet Session and native termination. Their existing success scopes do not include a native HAL half-frame/rate mismatch or all physical device changes. No tests were run or production fix proposed as proven by this audit.
