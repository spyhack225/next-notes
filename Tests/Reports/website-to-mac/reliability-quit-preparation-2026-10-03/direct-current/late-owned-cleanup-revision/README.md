# Post-`markBusy` stale-start cleanup: additive source review

**Held, off-source, uncompiled and unrun.** The frozen direct33 packet and the `direct-current` four-patch packet remain byte-identical. This additive review changes only the proposed late-input **fixed** `ParakeetEngine` branch after `await ModelRuntimeManager.shared.markBusy`; it is not a revision to direct33 or the late-input COMMON fixture. The preimage, target and patch hashes are in `manifest.json`. Both the replacement fixed patch and the small after-existing delta replay to the same target on disposable copied source; neither is a native verdict.

## First unowned write in the proposed branch

In current `ParakeetEngine.start()`, `generation` and the acquired `jobID` and stream `continuation` are local. `schedulerJobID` and `self.continuation` are shared actor slots. `await markBusy` is an actor suspension; `finish()` can increment `recognitionGeneration`, take and clear the current lane, and await a partial. Another `start()` on that **same engine instance** could also increment the generation and acquire/store a successor lane/continuation before the older start resumes. The prior late-fixed guard correctly refuses reopening input when stale, but its `await releaseSchedulerLane()` reads whatever is **now** in `schedulerJobID`, and its unconditional `self.continuation = nil` can erase a successor stream. The new guard would therefore add a producer-side unowned write even though its refusal decision is right.

The replacement uses the existing local `jobID`: only when the old `generation` is still current **and** the shared slot equals that exact `jobID` does it take the slot before awaiting `ComputeScheduler.shared.release(jobID)`. It always finishes its *local* continuation. It clears `self.continuation` only if its generation is still current after the release await. When superseded, it leaves successor slots untouched. There is no new field, Task, registry, await, timer or user-facing gate. The after-existing delta shows this one branch change; root should normally apply `late-fixed-owned-replacement.patch.txt` **instead of** `late-input-fixed-after-common.patch.txt` after the existing late COMMON stage.

This is a narrow correction. Earlier current-source `start()` refusal paths after `acquire` and `markReady`, its load-error cleanup, and `await oldPartial?.value` / `releaseSchedulerLane()` use shared slots across suspension too. `finish()` also clears shared fields in a deferred block after awaits. The patch does **not** claim those inherited paths are fixed. If an old start has already lost its slot, the local UUID alone cannot prove whether another path released it, so the new branch deliberately does not release that unowned lane. Full pending-start ownership and every start/finish interleaving remain open.

## Reachability and required actual regression

The production `DictationController` calls `makeEngine()` for each hold; its default `engineForCurrentSetting()` constructs a new `ParakeetEngine`. `EngineComparison` likewise constructs an instance for its one `measure()` call. I found no production caller that invokes a *successor `start()` on the same instance*. The controller can call `finish()` on its same engine while an earlier `start()` is pending, so a stale generation at this new branch is plausible; a concurrent same-instance successor slot is currently an API-level hazard, **not a verified user path**. `ModelRuntimeManager.markBusy` is a real separate actor transition and can suspend the engine, but source inspection alone does not prove the needed ordering occurred.

Before any acceptance, mount the late COMMON and run an **actual `ParakeetEngine.start()` producer-call** control with the confined public model and no owner assets. Capture local generation/job/stream identity at the actual post-`markBusy` return using default-nil diagnostic metadata, without substituting a fake model result. While that first start is suspended, invoke real same-engine `finish()` and, for the successor-slot negative, a second real `start()` on the *same instance*. Require observed ordering, distinct lane UUIDs and continuations, and a qualified first-start `CancellationError`; any missed overlap is INVALID. On ORIGINAL late fixed, assert the first broken shared-slot effect (successor lane released or successor stream lost) **at this branch** before running safety cleanup. On revised fixed, require this branch to leave the successor slot intact. The same fixture and inputs must run both versions, with all actually acquired lanes accounted for and exact source/public asset identities. If an inherited earlier start/finish cleanup clobbers the successor first, this narrow pair cannot qualify; stop and repair that producer path separately rather than grading a helper result. A forced diagnostic rendezvous may expose the legal actor interleaving, but it would not prove this scheduling occurs in ordinary dictation; do not label a helper-only or synthetic-model check end-to-end. The existing late19 fixture does **not** exercise a same-instance second `start()` or this post-`markBusy` branch, so its possible GREEN cannot validate this revision.

Direct33 remains independently source-admissible for root's serial ORIGINAL/FIXED native review. This addon holds the **late fixed branch** and any broader late-input promotion until the ownership branch and its actual producer-call qualification are reviewed. It supplies no model/native/build result, SIGSEGV cause, healthy typed-output proof or full quit guarantee.
