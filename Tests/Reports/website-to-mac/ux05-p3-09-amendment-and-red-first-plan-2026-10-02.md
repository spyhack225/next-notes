# Proposed P3-09 amendment for truthful UX-05 speaking

**Status:** off-source proposal, 2026-10-02. No roadmap, Source, build, install, native capture or owner store was changed in this audit. Coordinate with the runtime/P3-09 owner before applying anything. This proposal extends the [source audit](ux05-speaking-production-contract-2026-10-02.md); it is not an implementation claim.

## The conflicting specification

P3-09 step 4 in `04-PHASE-3-FULL-DUPLEX.md` currently says `case .speaking` calls `ActivationController.markListening()` and `IslandState.showAgentListening(transcript: "", level: 0)`, and `listeningFeed` may replace that card while `state.island == .speaking`. Its target behavior likewise says “`.speaking` → the listening card.” That deliberately hides output playback. UX-05 requires an actual *speaking* stage in the one companion's island. Mapping `.speaking` to the listening portrait would say the wrong thing, even though the reducer used a playback event.

The live shell is still `Mode.shadow` (`VoiceSession.swift:3–10, 78–94`); `publishIsland` is recorded but not executed. The reducer already accepts a matching `OutputID` and projects `.speaking` on `.firstAudio` (`VoiceContracts.swift:277–284`). The live island has no speaking kind (`IslandState.swift:113–121`). Legacy `RealtimeAudioSession.isSpeaking` becomes true when a clause **enqueues** (`RealtimeAudioSession.swift:582–594`) and must not drive UX-05.

## Text proposed for P3-09 target behavior and step 4

Replace only the speaking sentence in target behavior item 3 with:

> `.speaking` → a dedicated conversation speaking card and speaking portrait, with the short label “Speaking” and the companion's identity. Enter only for the current open voice session and current output after the playback backend acknowledges a positive played PCM buffer/sample. Queued text, model work, a stream opened without audio, and `player.play()` are not speaking evidence. A pending approval remains the actionable priority; an active user floor or confirmed playback pause takes the listening card. The readable reply notice after playback remains a separate result state.

Replace step 4's `case .speaking` mapping and related `listeningFeed` condition with:

> `VoiceSession` publishes `.speaking` through a single `IslandState.agentSpeaking` presentation; the island uses the companion's speaking pose and does not draw a microphone level or pending transcript on that card. `listeningFeed` updates only `.listening` (or an explicit user-floor override), never turns an active speaking card into a listening card just because a capture buffer arrived. `voiceProjection` is still the one session-owned projection, and worker writers remain gated. It is cleared on matched playback termination or session close. No extra island timer, audio path, or state store is introduced.

The view copy may say **“Speaking”**; diagnostics should say **“playback acknowledged.”** No backend receipt proves the sound reached a person's ears. Any answer snippet on this card must come from a committed, current answer; no synthetic typing or “heard” claim.

The reducer can use a small pure helper for projection precedence from its **existing state**; it should not persist a second display state or infer a pose from text. Proposed precedence is pending approval → confirmed user floor/paused output → confirmed actively playing output → response thinking → listening. Exact priority of an unrelated proposal remains with the current permission gate. This is a proposal for review, since the current P3-09 plan still owns the switch.

## Red-first installed production-path regression

Create one isolated `--selftest-island-voice-playback` fixture, or extend the installed island/voice test with the same coverage. It must enter via `AgentCaptureController.beginSession(captureAudio: false)` → actual `RealtimeAudioSession.beginSpokenReply/append/finalize` → real `AgentSpeechSynthesizer` backend callback → `VoiceSession.send` → `IslandState` → `IslandView` state. Use a self-test-only Apple voice selection and temporary/private test output. Do not read the owner's conversation, change saved voice settings or require a model, account, microphone or external app. Use a sentence long enough to observe playback before drain. The test may poll/wait in its harness; no sleep or await is added to the product path. A missing positive playback receipt is **ABSENT/FAIL**, never a green UI test. Existing `--selftest-voice-suspend-live` demonstrates signed-app Apple PCM playback, pause and drain; it does not currently assert the island or a resumed playback receipt (`AgentSpeechSynthesizer.swift:534–579`).

1. **Capture original red:** install a baseline with the new assertions before any fix. On queued output, assert no speaking card. On the real backend's first positive played-buffer callback, assert exact current `OutputID`/generation and `IslandState.kind == agentSpeaking` with one speaking portrait and no mic level. The original must fail specifically because live island remains listening/working, while reducer may already say `.speaking`; preserve that log and binary/source identity. This reproduces the user's missing speaking-stage path rather than only a pure reducer trace.
2. **Pause/resume original red:** after onset, invoke the real `RealtimeAudioSession.pauseForListening(captureID:)`; assert output pauses, island changes to listening immediately, mic capture can remain live and no clause is cancelled. Invoke `resumeAfterListening` with the same capture ID; assert the island remains non-speaking until a *new* positive playback receipt for the same output and post-pause epoch, then speaks. The current reducer fails both the pause projection and the premature resume assertion. Test a wrong capture ID, stale output generation and callback queued before pause.
3. **End/stale positives:** natural drain → listening/result; barge `noteUserSpeech` and session close → no speaking; A replaced by B → late A first/finish/resume callbacks cannot activate or clear B; silent/zero-frame or synthesis-only run → never speaking; failure/fallback → only the new acknowledged playback can start it. With a pending approval, the card stays actionable and a background worker cannot replace the conversation card. These should exercise the same producers and inspect the actual island consumer, plus pure reducer cases for each transition.
4. **After producer fix:** rerun the *unchanged* original assertions on a new installed binary and all focused `--selftest-island`, `--selftest-avatar`, `--selftest-voice-session-reducer`, `--selftest-voice-duplex-work`, `--selftest-voice-suspend`, live suspend, voice lifecycle and latency gates. Record exact markers, binary/source identity, unchanged owner stores/defaults and first-visible transition time. Native one-mark/reduced-motion/VoiceOver review remains separately required; the self-test does not prove a person heard audio or that the physical island is visually correct.

The current recorder-backed reducer self-test (`VoiceSessionReducerSelfTest.swift:176–207`) is useful for identity and ordering but calls `notifyTestingFirstAudio` itself, so it cannot substitute for the real backend/actual island regression. The pure traces currently expect `.publishIsland(.speaking)` after firstAudio but not the pause/resume presentation. Both levels are needed.
