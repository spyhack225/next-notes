# Computer readiness row: responsive alternatives and orb clocks

Status: **read-only source audit** of the applied app36 row. No Source edit, build, install, native interaction, or staging was done for this audit. Current `ComputerBrowserReadiness.swift` SHA-256 is `513e885becca8306b95a13bde2fea217106d0fddaa086f55766ac30ca1b6f5df`, matching the app36 source manifest and the prior combined proposal's copy.

## Actual producer and change

- `ComputerBrowserReadiness.agentBrowserRow` is the only `ReadinessRow` that passes `busy`. It supplies `.connecting` when `isWaiting` is true (lines 116–135). Initial/live `refresh()` starts `refreshCDPState()`, which sets `.checking` before its asynchronous probe; with `setupState == .idle`, that makes `isWaiting` true until the accepted probe result is set (lines 213–230). The isolated `--selftest-settings-sheet` fixture explicitly skips `refresh()`, so it starts with `busy == nil` (line 214).
- The original tracked row had one horizontal status/action/orb expression. The applied app36 diff replaced it with `ViewThatFits(in: .horizontal)` and two native alternatives; each refers to `statusAndAction`, whose `if let busy` constructs `ThinkingOrb` (lines 259–302). At a busy render the source therefore contains **two possible animated orb subtrees**, one in each layout candidate. This is an admission risk, not proof that two schedules are active simultaneously.
- `ThinkingOrb` defaults `isAnimated = true` and, when Reduce Motion is false and no `frameInterval` is supplied, uses `TimelineView(.animation(paused: false))` around its `Canvas` (`ThinkingOrb.swift` lines 34–69). The row passes neither `isAnimated` nor a frame interval. Reduce Motion takes a constant canvas and creates no timeline. The row's `ThemeBorderBeam` and `ThemeVoiceGlow` are not present; their separate implementations stop their clocks for `isAnimated: false` or Reduce Motion (`ThemeBorderBeam.swift` lines 63–68; `ThemeVoiceGlow.swift` lines 85–90).
- The `setupState == .started` branch is a separate source-backed continuity gap: after the synchronous launch returns, the producer labels the row “The agent browser is starting…” and polls up to 16 times with a 500 ms wait plus each probe, but `isWaiting` becomes false because it accepts only `.starting` or `.checking` while `.idle` (lines 130–135, 143–145, 197–209). Thus the busy orb is removed during a period the same producer still calls starting. This is a code-path inference, not a timed native observation.
