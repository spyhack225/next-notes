## Dictation: key down → insertion or recoverable failure

| Moment and event source | Present behavior in production source | Desired UX-08 behavior / verification |
|---|---|---|
| Hotkey or Record button → `DictationController.beginDictation` | At key-down the controller captures the insertion origin, output profile, and screen context; sets `.starting`; then starts asynchronous microphone/engine work (`DictationController.swift:1220–1339`). `DictationController.State` distinguishes idle, starting, listening, finishing, error (`:337–354`). `HUDPanel` is nonactivating and never takes focus (`HUDPanel.swift:1–39`). | Preserve target capture at key-down and immediate controller feedback. Measure key-down → HUD first visible pixel and key-down → actual capture separately; the existing `dictation.keyDown_to_capture` trace measures the latter, **not** HUD visibility. No new await or sleep before capture. |
| Capture and provisional words: `isCapturingAudio`, `level`, `transcript` | HUD uses actual capture state, a red recording indicator and live level; `.starting` says Getting ready until the mic opens, then Listening. Real ASR updates `controller.transcript` (`HUDView.swift:34–89`). `DictationStatusBand` says Getting ready/Recording/Transcribing from the same state, though its `.starting` branch does not inspect `isCapturingAudio` (`DictationStatusBand.swift:80–115`). | Preserve the distinction between opening and hearing. Audit simultaneous HUD/band wording on a slow startup; use the existing capture boolean if the two surfaces disagree. Keep the native history list and one orb. Measure first partial from the existing speech-to-partial trace. |
| Release → `endDictation` and tail | Release during `.starting` keeps pre-roll and proceeds through the normal tail; release otherwise enters `.finishing` (`DictationController.swift:1591–1657`). HUD retains real transcript if one exists; otherwise says Transcribing. The run is recorded before injection so failed insertion leaves text in history (`:1871–1886`). | Expose actual transcribing/cleanup stages if their producer events are available; do not infer them from elapsed time. Keep the HUD responsive while finalization runs. Verify switching apps after key-up still targets the key-down app. |
| `TextInjector.insert` outcome | Insertion uses captured `origin`, and records injection duration plus key-up-to-injection latency (`DictationController.swift:1887–1909`). `.inserted` plays an optional sound and `finishIdle` immediately sets `.idle`/clears the transcript (`:1938–1986`); the HUD therefore has no persistent visual “landed” moment. `.copiedByChoice` similarly returns idle. `.couldNotReturn` gives an error saying the text is on the clipboard; the prior `RunLog` record remains recoverable (`:1956–1964`). Errors remain visible three seconds (`:2357–2376`). | A successful completion cue must be driven by the actual `TextInjector.Outcome`, distinguish inserted from copied-by-choice, and must not imply insertion before the injector returns. Do not add a second outcome store or delay the next hold; identify the smallest existing state/event seam before implementation. On failure, point to the saved transcript and one concrete recovery action while keeping clipboard truth. Capture inserted, copied, and could-not-return paths. |

`HUDPanel`/`HUDView`, `DictationStatusBand`, `TranscriptionRow`, `RunLog`, `TextInjector.Outcome`, `RecordingIndicator`, `LevelBar`, `ThinkingOrb`, and `DictationController.State`. `DictationView` already seeds its elapsed counter from `holdStarted` when opened mid-hold (`DictationView.swift:102–156`) and retains native selectable list behavior (`:179–215`). Do not turn the usage log into UI state.
