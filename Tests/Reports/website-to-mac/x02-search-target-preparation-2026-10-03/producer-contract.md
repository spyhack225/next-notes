# X02 exact conversation turn anchor: producer contract

**SOURCE AUDIT ONLY — UNRUN.** This is a proposed contract, not a code patch, compiled regression, search migration, or live navigation result. The frozen X02 display-cap packet and its isolation add-on remain separate and unchanged. `audited-source-pins.json` records only the finite source files read for this audit.

## First loss and current consumer

`AgentSession.Message.id` is a persisted UUID (`RealtimeAgent.swift` 1004–1030, 1602–1634). `AgentSession.endSession` hands real message rows to `KnowledgeIndexer.connect` as a `ReviewRequest` (`RealtimeAgent.swift` 1178–1207; `KnowledgeIndexer.swift` 309–313). The first producer loss is `KnowledgeIndexer.conversationSession` (858–863): it copies role, text, context kind, source and time into `KnowledgeConversationRow`, but discards `Message.id`. `Chunker.conversation` (214–247) then makes one indexed passage from a user row plus zero or more plain assistant replies. `KnowledgeChunk` has no origin field; the chunk table, `replace`, generation hash, search SELECT and `KnowledgeHit` omit the ID (`KnowledgeStore.swift` 29–38, 280–293, 347–389, 492–522; `KnowledgeSearch.swift` 45–68, 129–221). `KnowledgeCitation` omits it from construction and its deliberately compact codec (`KnowledgeAsk.swift` 14–89).

The Search, Ask and Agent citation actions therefore call parameterless `NavigationState.showConversation()` (`KnowledgeSearchView.swift` 287–299; `AskView.swift` 424–436; `AgentView.swift` 510–519; `NavigationState.swift` 291–297). That selects a pane, with no source or row focus. `chunkID` is a SQLite row ID, `ordinal` is a position within one generation, and `occurredAt` is rounded to seconds. None is the originating message UUID.

## Minimum exact **turn** anchor through the existing index

1. Add an optional `originatingUserMessageID: UUID?` to `KnowledgeConversationRow` and copy `Message.id` in `conversationSession`. Keep existing pure/test row initializers compatible with `nil`. In `Chunker.conversation`, assign the current **user** row's UUID to its one `KnowledgeChunk`. The chunk represents that turn. This is an exact user-turn anchor, including when the search words occur in a reply. It is not an exact assistant-reply anchor; a reply-level promise requires per-message chunks or an explicit span-to-message map, separately designed and tested.
2. Carry this optional ID in the existing `chunk` table as a nullable text column, through `KnowledgeStore.replace`, `KeywordKnowledgeSearch`'s common column projection and all keyword/browse/vector-ID hit readers, `KnowledgeHit`, and `KnowledgeCitation`'s compact codec. Parse only a valid UUID; malformed/NULL data has no exact target. Do not encode UUIDs in heading, snippet, text, timestamp, ordinal or `source_id`; the latter remains the conversation/session ID used for grouping, deletion and provenance.
3. Add the nonnil tagged UUID to `KnowledgeStore.generation(of:)`. `nil` contributes no new hash bytes, preserving existing generation behavior for legacy and non-conversation sources. A same-text passage with a different exact origin must produce a different generation and replace its source transactionally. The `chunk` column is additive and nullable on schema-version-1 databases. Do **not** simply bump `schemaVersion`: `openLocked` (202–218) deletes/rebuilds on a version or opening error, and an indexed older conversation may no longer exist in the 120-row JSON history. An additive migration failure must be surfaced without falling into that destructive repair path; distinguish migration refusal from genuinely unreadable/corrupt derived data.
4. Carry the source generation with `KnowledgeHit` and saved `KnowledgeCitation`, in addition to the source ID and exact UUID. A captured hit or persisted citation can outlive a reindex or deletion; SQLite chunk row IDs can be reused. The click resolver must validate the current row's **kind + source ID + generation + chunk ID + origin UUID** in one store-locked read (including current `index_state` generation) before constructing a typed navigation target. Generation is this index's deterministic source fingerprint, not a global database identity or cryptographic proof; the live tuple check supplies the necessary current-row evidence. Checking a cached `chunkID` or UUID alone is insufficient. No second ledger, queue, model pass or conversational await is required.
5. The typed target identifies `(conversation/session UUID, originating user-message UUID)` and carries a repeat-jump token. The Agent pane must resolve that pair against the actual retained `AgentSession.messages` before scrolling to its existing `message-<UUID>` row ID. A missing raw row never becomes a jump to the current, unrelated conversation. The indexed passage may remain readable in Search; its exact Agent jump is unavailable. A citation chip must communicate that state rather than silently selecting the Agent pane.

## Legacy, overwrite and deletion boundaries

`KnowledgeIndexer.backfill` (498–510) deliberately skips already indexed conversations: reindexing an old session from only the newest raw rows would delete older indexed passages. After the nullable migration, those preexisting passages keep `NULL` origin IDs. Do not force a reindex or guess an ID from text/time/ordinal. Enrichment is admissible only when complete source equality against the currently indexed passage set is established; leaving legacy rows unlinked is the safe default. New session-ended indexing can carry IDs going forward.

`startNewConversation` indexes its ended session and clears active JSON (`RealtimeAgent.swift` 1524–1544). A hit may therefore have a valid indexed UUID but no retained raw row to scroll to. The same applies after the 120-row trim. *Forget all conversations* removes the index source; a stale screen hit or saved citation must fail the current-row guard. Duplicate text and equal timestamps cannot make a legacy `NULL` anchor unique. Explicit memory correction does not rewrite historical conversation words or receipts and is a separate X02 acceptance path.

## Red-first production-path verification

Extend the existing `--selftest-index` temp path at `KnowledgeIndexSelfTest.swift` 178–243. It already creates an injected `AgentSession` with temporary file/fake clock, temporary `NextMemory`, `KnowledgeIndexer`/`KnowledgeStore`, connects the real session hook, ends a session, drains the actual index, searches it, and exercises New conversation/Forget. Add the same unchanged checks to original and fixed builds:

- Capture a real user `Message.id`, end and index the session, search its question and answer words, construct the actual `KnowledgeCitation`, encode/decode it through a saved `AgentSession.Message`, and assert the search hit/citation/typed target carry the same exact turn and generation. Original source must fail that missing-identity assertion before the fix. Reopen the temporary conversation file and verify the typed target finds that same retained row/session; a matching text in another session must not satisfy it.
- Add duplicate text with equal-second timestamps but different UUIDs, a same-source/same-text changed-origin generation case, and a stale pre-replacement hit/citation. The current-row resolver must refuse the stale generation; keyword, browse and vector-ID hit paths must agree on identity.
- Seed an actual schema-version-1 index with an older indexed-only conversation before the fixed reader opens it. Assert migration preserves source count, FTS text, generation and older-only passages; the optional ID stays `nil` and no target is invented. Test migration refusal as a visible, non-destructive error. Do not reindex from a partial 120-row source.
- Delete/forget the source after capturing a hit, then verify neither its stale result nor a saved citation opens an unrelated row. After New conversation or the raw 120-row trim, an index-only passage stays searchable but has no false Agent-row jump. Preserve unrelated sources and deletion watermarks.

`KnowledgeTypedRouteSelfTest.swift` 72–100 is the existing saved-citation codec/consumer check to extend for optional UUID/generation while preserving no duplicate passage-body persistence. The pure `Chunker` and store tests remain necessary, but helper success alone cannot replace the hooked `AgentSession → Indexer → Store → Search → Citation → Navigation` path. An offscreen/native Agent scroll and accessibility action still need a separate qualified host; this audit asserts no UI acceptance.
