## Co-owned files that block blind whole-file commits

- **NextNotesApp.swift:** theme launch registration, packaged-font gate and onboarding/Settings-sheet registrations share the file with exact diagnostic-launch validation, core dictation delivery regressions, meeting integrity/retention/resource-admission registrations and ACP termination coverage. Root owns integration. A full-file commit must bring those owners' dependencies; a scoped theme commit requires their reviewed hunk boundaries. In particular its new MeetingRetentionChoiceSelfTest reference requires the corresponding currently untracked source if that registration is included.
- **Makefile:** both ThemeFonts and OpenPeeps resource copies are currently one nearby diff. Keep each included producer's packaged resources; obtain illustration-owner signoff rather than discarding its copy.
- **DesignSystem.swift / OnboardingSteps.swift / SettingsSheet.swift:** canonical theme, illustration/practice and isolation/layout changes overlap. A recent two/four-file patch is not the complete HEAD-to-current contract. Review the complete current diff with owners.
- **27 isolation files:** several are runtime/model/calendar/meeting-owned, not UI-owned. Include the diagnostic-specific hunks only after those owners approve; do not absorb unrelated live runtime changes merely because they share a file. The existing handoff is the authoritative scoped starting point, with current hashes supplied here.
- **Core dictation:** DictationController's Delivery/latestDelivery/hold-observer seam already exists in HEAD and is unchanged now. DictationStatusBand/View currently add actual delivery status and retry consumers; NextNotesApp adds focused delivery regression coverage. This is UX-08/core-owner work, not a new prerequisite Source rewrite by this audit. Coordinate it separately; do not lose the current OnboardingSteps receipt consumer.
- **AgentView ownership:** another source owner may be active; identity and handoff are unconfirmed. Its current hash is a snapshot, not ownership evidence. Root must resolve that lease before any staging or follow-up change.
- **Other runtime work:** RealtimeAgent/tool-loop/harness work, Computer/HumanInputWatch and browser changes, meetings reliability/resource probes, Llama/NotesModelRuntime, ModelDownloader and new ExplicitMemoryStatement sources remain with runtime/core owners. Their unrelated live changes are not justified by the Settings visual result. AgentPresentationSelfTest supplies the existing typed-stream presentation checks; the proposed motion instrumentation is unapplied. It is not required merely to supply the theme types. StoreIsolationSelfTest progress instrumentation is likewise a separate owner change.

ExperienceSheet and MeetingConsolePreview consume the shared fixed-light theme and native rendering/isolation paths; their exact current hashes are included as diagnostic dependencies for their respective claimed evidence, not requirements for a Settings-only production fix. README/site content edits and generated caches are not runtime font/resource dependencies. `site/DESIGN-SYSTEM.md` and AGENTS record the normative design/owner decision; keep those policy changes reviewable separately.
