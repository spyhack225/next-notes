No canonical source, Coordinator, frozen quit packet, owner ledger, model, asset or installed app was changed. A source replay is neither a Swift verdict nor an original/fixed quit result.

## Actual ownership and first failure contract

The current loaded-only Manager seam is `AgentTaskManager.sharedIfLoaded` (`AgentTaskManager.swift:7–14`). Its one `running` map holds `.voice` (optional exact `Task<Void,Never>`), `.worker` (`Task<Void,Never>`), `.scheduled` (`Task<ScheduledRunOutcome,Never>`) and `.returnedVoice` (already returned) handles (`33–77`). `startVoiceWorker`, `beginScheduledRun(_:executionOwner:)` and `enqueueWorker` put the actual operation in that map (`715–777, 483–506, 1296–1301`). Normal conversation Done intentionally leaves this work alive; it is not a quit path.

The first source-level ownership gap is `cancel(_:)`: after a successful primary cancellation it cancels a local `.worker` handle and immediately clears `running[id]` (`930–976`). Its backend may still be inside a tool; a later process-quit snapshot of the same map cannot join that dropped Task. This is a source-backed risk, **not** a reproduced product failure. The scheduled cancellation path already retains its slot, and voice cancellation retains its exact Task until outcome return (`940–974, 848–865, 748–763`). No stored `.cancelled` status or receipt is treated as actual cessation.

## Candidate boundaries

`AgentTaskManager.swift.patch.txt` adds one process-quit-only admission flag to the existing Manager. `beginProcessTermination()` synchronously captures the *existing* map's handles and cancels them all; its returned MainActor closure awaits their exact `Task.value` results. It adds no Task, queue, ledger, timer or second map. Map admission checks refuse new voice, scheduled and local operations after that capture. Normal Done does not call the method. The local cancel path retains a canceled worker in its same map slot; a token on that row prevents its own operation-body cleanup from erasing a successor's slot. The candidate does not alter durable task status, approval, receipt, effect or retry authority.

`NextNotesApp.swift.patch.txt` calls only the already-loaded Manager at the synchronous AppKit quit entry, alongside the captured Notes task handles. It awaits the captured Manager closure in the existing termination Task before `NotesModelRuntime.finishTermination()` and AppKit's final reply. This leaves the existing recording choice, `drained` predicate, diagnostic veto, one-shot safety drain, S1/Notes/ASR/Pocket order, and `applicationWillTerminate` unchanged. The Core `withBoundedWait` helper and ordinary voice Done are untouched.

## Held seams and limits

- `ScheduledRunner.run` creates its `Task<ScheduledRunOutcome,Never>` before `runBody` reaches `Manager.beginScheduledRun` (`ScheduledRunner.swift:275–329`). If quit arrives during its route/model preflight, the Manager map has no handle to capture. The candidate's later `beginScheduledRun` refusal prevents a routine tool from starting, but it does not prove that provider/model preflight has returned. That separate owner must be traced and qualified before an all-background safe-exit claim; this packet does not patch ScheduledRunner.
- The private AppDelegate fixture injection and a real asynchronous backing-return seam are outlined, not implemented. Existing isolated `AgentTaskManager(store:)` and `TaskWorkerAttemptSelfTest` supply storage/tool call patterns, but no current fixture establishes the required Cocoa overlap. There is no compiled original RED or fixed PASS, no native/process quit or latency measurement, and no assertion that physical capture, voice playback, external effects or SIGTERM are safe.
- Even a joined Task cannot infer whether an already-entered consequential effect ran. The existing receipt/primary record remains authority; no automatic repeat follows a refused save. A failed AppKit drain can leave the process alive with owners closed, as in the current quit path; this proposal does not add restart/recovery behavior.

This candidate is for serial-root review and native qualification only. Its preimage pins can drift while the runtime owner edits Manager; recheck every pin before any mounting decision.
