## What the patch actually preserves and joins

The producer patch leaves the `endSession`/normal Done and `stopEngine` bodies byte-identical. It adds no await to normal Done. `beginProcessTermination` is a new App-only synchronous close that snapshots the currently registered engine and six actual Task fields before clearing their slots, then cancels all fields and finishes the streams. `finishProcessTermination` awaits those captured values in file-feed, decoder, Apple feed, engine-finish, Apple result-consumer, active-turn, VAD order. All cancellations happen before those awaits. There is no new Task, queue, timer or model pass in either process-quit method. The API must be called once from a separate existing App termination Task; invoking finish from a captured worker could self-join.

This ordering is coherent for **registered** work. The decoder Task directly awaits detector preparation/process and closes the same detector before returning (`AgentCaptureController.swift:615–753`); the feed Task directly awaits Apple feed (`755–790`); Apple result consumption ends after engine finish (`AppleSpeechEngine.swift:97–113`). Awaiting the exact Task is stronger than treating cancellation as return. It still does not prove SDK-global quiescence or physical microphone/output stop.

## Actual source boundaries still open

1. **Unpublished Apple startup is not owned by the snapshot.** `startEngine` creates a local `AppleSpeechEngine`, then awaits `preferredInputFormat` and `engine.start` before assigning `self.engine` (`AgentCaptureController.swift:571–603`). Process quit can clear `captureSessionID` and capture no engine during either await. The resumed `startEngine` checks the ID and calls `engine.finish`, but the App quit path has no captured handle to await that late finish. This is a concrete source-level missing join path, not measured overlap or a reproduced crash. The proposed `hadCapture = captureAudio && engine != nil` correctly limits unsubscribe to a published microphone engine; it cannot cover the unpublished local one.
2. **Retired and separately spawned work remains outside the fields.** Normal `stopEngine` clears feed/decoder/consumer/engine slots before its existing bounded waits (`961–993`), so a later process snapshot cannot recover a timed-out predecessor. Existing frontend/conversation preparation and staging Tasks are not fields in this snapshot (`372–408, 1088`), and active-turn cancellation does not join background Manager/model work. These are explicit packet limits, not findings that the new patch makes normal Done worse.
3. **Late publication needs production-path proof.** The added guards close `beginSession`, `beginFileSession`, `startEngine` entry, deferred feed, VAD, and `emitTurn`. A preexisting `beginSession` has capture-ID checks after its microphone permission await; `startEngine` checks the ID after both awaits before publishing. The private input-producer hold in `emitTurn` also rechecks `isSessionActive` after its await. These source checks support refusal of those late publications, but their exact behavior across real native/fixture callbacks and AppKit first/final replies is unrun. A returned nil ownership snapshot is not a safe-exit verdict.

The packet has no actual original/fixed Cocoa input conductor. The required fixture must hold a genuinely entered native/registered producer through first `.terminateLater`, keep private continuations releasable, prove the original failure before the same fixed assertions, and observe real final reply only after same-handle return. Normal Done and foreground bounded wait remain separate controls. The parent composite App patch stays held while the Manager candidate has post-quit continuation/retained-slot issues and Capture has the above excluded owner paths.
