## Two incomplete producer contracts

1. **Same-ID handle replacement.** The frozen candidate retains a canceled local `.worker` in the existing `running[id]` slot until operation-body return, but its `enqueueWorker(_:)` still assigns `running[id] = RunningWorker(...)` without checking for a predecessor (`AgentTaskManager.swift:1296–1301`; candidate patch hunk `+1320`). The token added by the candidate prevents an old closure from erasing a *successor* slot; it does not retain the old Task once the successor overwrites that slot. Current `releaseWorker` explicitly comments that a queued explicit continuation may own the next handle before the predecessor releases (`1303–1314`). Thus a quit snapshot can only promise to join the handle present in the map, not every previously canceled operation. Source does not establish a production same-ID successor while its predecessor is still in consequential backing: the visible continuation callers require a waiting row and normally follow a backend return. Treat this as a missing ownership invariant/qualification, not a reproduced duplicate-effect bug.
2. **Post-quit continuation commits.** The candidate guards only inside `enqueueWorker(_:)`. Three actual continuation producers make their durable transition **before** calling that function: `approveCompatibilityCLI` commits `.queued`, inserts a one-shot token and returns `Void` (`981–996`); `respondRestoredPermission` commits `.queued`, inserts approval and returns `true` (`1139–1167`); `respondInput` commits `.queued` and returns `true` (`1231–1245`). During a pending AppKit `.terminateLater`, a callback arriving after the proposed `processTerminationRequested` flag can therefore report or retain accepted queued work while `enqueueWorker` silently refuses to create its worker. These are real call sites and an unsound candidate ordering; an actual late callback/Cocoa fixture is still needed before calling it an observed product failure. The admission decision belongs before the primary write/token/result for each producer, with existing permission and effect semantics preserved.

`ScheduledRunner.run` creates an operation before Manager admission and performs route/model preflight before `beginScheduledRun` (`ScheduledRunner.swift:275–329`). The frozen README already holds that owner and does not claim that a Manager snapshot covers it. Normal voice Done and the default-false foreground bounded wait remain separate from process quit.

## Required next evidence

Use the same isolated Manager, primary store and actual temporary-tool backing in an AppKit termination fixture. Hold the actual backing across the first `.terminateLater`; call the real continuation producers during the pending quit, then release backing and observe the final reply. A second case must qualify whether a same-ID successor can coexist with a predecessor still in backing. Original and fixed inputs/assertions must be identical; unobservable overlap is an invalid fixture, not a passing or failing verdict. No saved cancellation/approval or receipt alone proves actual return or external effect outcome. The private fixture injection/backing seam remains unimplemented, and the frozen patches must not be mounted as complete process-quit ownership.
