# Safe metadata root for the actual Settings initializer: independent review

**Design only; no source patch, compiler, native process, model asset or preferences read/write.** Eight exact source hashes are in `source-pins.json`. This reviews a paired original/fixed Notes diagnostic that must exercise the real `Settings.shared` initializer while keeping the original eager diarization availability read away from the owner's model directory.

## Existing getter and usable seam

`MeetingDiarizer.isDownloaded` is synchronous and `nonisolated`. It already selects a confined copied-asset root for `NativeDiarizationQuitSelfTest.isRequested`, then executes its real `FileManager.fileExists` checks and partial-file enumeration. The ordinary branch selects `modelsRoot` under Application Support. The existing diarization validator **cannot** be reused for an empty metadata root: it requires four compiled models, PLDA parameters and audio. The useful seam is only the getter's root selection, before the unchanged filesystem checks.

For one exact Notes diagnostic variant, a narrow root branch could select an **already admitted, direct temporary, empty metadata directory**. The required model-relative paths would be absent there, so the actual first `fileExists` returns false; no answer is injected. Original `Settings.init` with explicit false would enter that getter once; the fixed lazy `diarizeChoice ?? MeetingDiarizer.isDownloaded` would skip it. Nil choice would still enter the same getter and resolve false against real absent files. Explicit true and false would retain their values. This measures the responsible initializer decision without reading the ordinary model root or creating a second Settings/store instance.

This branch must be keyed to the complete exact Notes mode, not every `--selftest-native-termination` run. Existing startup/diarization fixtures retain their copied-asset route and ordinary launches retain `modelsRoot`. The new mode's root can be a validated empty subdirectory of the admitted copied-GGUF temporary root, or another direct UUID temporary child; in either case its metadata path must be validated before `NSApplication.shared`, must be nonsymlink and confined, and must have no required diarization files. Using the copied GGUF root directly is possible only if its proposed allowed-file contract explicitly admits the metadata subdirectory. Do not point the getter at a missing unvalidated path or at `MeetingStore.isolated(at:)`; neither is a metadata-root admission check.

## Actor and fail-closed requirements

The getter is nonisolated and cannot synchronously read mutable `@MainActor` admission state from `NativeTerminationSelfTest`. There is no present nonisolated immutable Notes metadata-root accessor or pre-AppKit trace. Before authoring COMMON, choose a source-backed way for the getter to derive/revalidate the same immutable argument-bound root, or expose a safely published immutable Sendable admission value. Do not hop to MainActor from the synchronous getter, add a waiter, or use a process-wide generic availability override. A single already existing native diagnostic trace may be extended with bounded scalar counts only if it is created before the first `Settings.shared` touch and is safe to call synchronously from this nonisolated getter.

The exact Notes branch must be chosen **before** any fallback to ordinary `modelsRoot`. If its root is missing, symlinked, mismatched or replaced, refuse the diagnostic; never fall through to the owner's directory. Since `isDownloaded` returns `Bool` rather than `throws`, a failed branch may return false only while retaining an INVALID signal that the pre-AppKit validator/arm checks before any successful verdict. A false value alone would disguise invalid input as an ordinary absent model. Recheck confinement at the getter boundary before real filesystem checks; path validation is still not an atomic defense against adversarial replacement between check and use, so the serial owner must state that practical limit and retain exact source/file identity evidence.

A nil-default scalar probe should record actual getter entry and selected root category at this same boundary, before the real `fileExists`, without returning a substitute availability value. It must be silent outside the exact mode. Counts must be from fresh processes because `Settings.shared` is one singleton: with the same COMMON fixture, original explicit false/true enter once, fixed explicit false/true enter zero times, and nil enters once in both. The probe cannot alone prove the filesystem route; the exact root admission and unchanged getter checks supply that part. No counts are claimed as executed here.

## Preference ordering and retained Notes owner

`--selftest-native-termination` does not allow saved model selection. `SelfTestHarnessDefaults.suite` is already a per-process isolated domain and is selected by `Settings` under `SelfTest.isRunning`. Before `NSApplication.shared` or `AppDelegate()` and before any `LlamaBackend.initialize`/`NotesService.notesBrief` first touch, seed the existing `"meetingsDiarize"` key as explicit true, explicit false, or absent for separate cases. `Settings.Keys` is private; a fixture using the literal must assert that the actual singleton reads the intended `meetingsDiarizeChoice` and resolved value. Do not call `chooseDiarization` to seed, since it requires `Settings.shared` and crosses the test boundary too late. Keep the fixture's one private NotesService, one fixture meeting and existing `beginTermination` captured Task join; the root change concerns metadata availability only and grants no new Notes Task owner.

The existing `NativeTerminationSelfTest.runStandalone` can validate exact arguments before AppKit, but its current Notes arm creates the runtime, store, model trace and `Settings` consumers later. The eventual fixture must prove validation/seed precedes the first singleton access in a fresh owned process and classify a late bootstrap failure INVALID rather than call the generic native-arm catch's Cocoa quit path. This is a prerequisite design, not a mounted patch or a native shutdown verdict.

## Review of the proposed exact-mode contract

The proposed `--native-notes-settings-case` values (`stored-on`, `stored-off`, `automatic-missing`, `notes-active-off`) make the root-selection scope concrete. A pure, immutable argument-derived admission can be validated in `runStandalone` before `NSApplication.shared`; the three settings-only modes can seed the existing per-PID suite, instantiate the actual `Settings.shared` once, check its actual choice/value/probe count, and exit without AppKit or weights. `notes-active-off` uses the same admitted false seed before AppKit, then the existing private Notes/runtime/actual Cocoa path. This is a genuine singleton initializer test, not a call to the pure helper or a reset instance. Exact flag validation must reject mixing these modes with startup, recording, other-owner and background cases.

The cross-actor type needs care. `MeetingDiarizer.isDownloaded` is `nonisolated`, whereas `NativeTerminationSelfTest` and `Settings` are `@MainActor`. The getter may read a `nonisolated` immutable admission only if its complete value is `Sendable`. Use a concrete `Error & Sendable` failure type if representing it as `Result<Admission, Failure>`; an existential `Result<Admission, Error>` does not by declaration guarantee Swift 6 Sendable conformance. The admission's URL/mode values must be immutable. This is a declared-type constraint, not a compile verdict. The optional scalar callback belongs at the real `Settings.init` RHS on MainActor, installed before `Settings.shared` first touch. The nonisolated getter should not call that actor-isolated callback.

For `automatic-missing`, the admitted empty `settings-availability` directory lets the unchanged getter run real `fileExists` on absent required paths. Explicit on/off in the fixed producer skip the getter; in the old producer they enter it and consult that same private directory. The exact-mode branch must take precedence over the ordinary `modelsRoot` fallback. If its immutable admission fails or the directory changes before getter use, never use `modelsRoot`; return an unavailable Bool only with a retained INVALID condition that the standalone caller checks before reporting a result. The getter should revalidate the directory/path at use, while acknowledging that a path check followed by `fileExists` is not an atomic filesystem binding. A previously valid static `Result` alone cannot detect a later replacement. No broad SelfTest switch, fake availability Bool, unsafe global mutable pointer or MainActor hop is needed.

The settings-only modes need no GGUF open. The `notes-active-off` mode still must configure the explicit copied-file runtime override and prove actual native overlap and Cocoa votes separately. All four modes require a fresh process and identical COMMON admission/probe semantics before an original/fixed comparison. No source code or executable result was produced by this review.
