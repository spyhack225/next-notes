# Notes native owner / Cocoa quit prerequisite: independent design review

**Source only; unimplemented, uncompiled, native UNRUN.** This review uses only the ten source files in `source-pins.json`. It does not read a model, owner store or asset, alter a frozen packet, or rebase Manager. It assesses a genuine in-flight NotesService task and NotesModelRuntime native call, separate from the imported-pending Manager fixture.

## Is an exact Notes task getter needed?

For a **new private `NotesService`** with one saved fixture meeting UUID and exactly one `summarize(meeting, using: .appLLM, announce: false)` call, **no**. `summarize` checks `tasks[id] == nil` and `terminationRequested == false`, then assigns its returned work to `tasks[id]`. The map is `[UUID: Task<Void, Never>]`. `beginTermination()` synchronously sets `terminationRequested`, copies `Array(tasks.values)`, cancels those same handles and returns the copy; the existing App task awaits each captured `.value`. At the actual first Cocoa reply, `ownedTaskCountForTerminationTesting == 1`, together with the private service/unique fixture meeting/only submitter, means the sole retained map handle is the one captured. No replacement can be submitted after `beginTermination()` closed admission. The existing `NativeTerminationSelfTest` already uses this private service, one summarize call, count-one observer, actual App delegate and final count-zero check.

This conclusion requires the fixture never call `NotesService.cancel(id)`, which intentionally removes the UI slot before operation return, and never expose its private service to another submitter. If a future case admits multiple meetings or independent cancellation, count one would no longer identify the fixture task; only then would an admitted, read-only exact-ID handle lookup or an explicit capture assertion be justified. An extra getter now would duplicate the existing map's owner merely to restate a one-task invariant.

## Native overlap and admission

The existing `configureTerminationNativeFixture(modelFile:observer:)` is the correct bounded runtime seam. It validates a direct temporary UUID root with prefix `NextNotesNativeTerminationTest-`, a regular nonsymlink file and exact expected byte count while the runtime has no model/load/native owner. `openNative` and the metadata read both use `modelFileForTerminationTesting` when set. `ModelSpec.fileURL` derives Application Support plus `fileName` and ignores `ModelSpec.url`; passing a copied file as `url` alone would load the wrong location. Any new pre-NSApplication admission must use a path compatible with that existing prefix or explicitly qualify a narrow validator change. A copied public GGUF needs independently pinned source identity/hash and stable copied bytes before *both* original/fixed runs; the current runtime guard is size/path validation, not proof of public source identity or immunity to later path replacement.

`decodeNative` invokes the observer immediately before and after actual `llama_decode`. The existing trace schedules Cocoa quit on `RunLoop.main.perform` after a prior successful decode and a new entered bracket. That asynchronous hop **can miss overlap** if the native call returns before AppKit invokes `applicationShouldTerminate`. The actual delegate observer must require the entered bracket still active (`inFlight == 1`), prior success, and the private service's count one at the first `.terminateLater`; missing overlap is INVALID/unavailable input, not a producer RED or a green drain. The hook itself must stay free of sleep, blocking locks on native objects, or direct `NSApp.terminate` from a Swift MainActor model job. The real App snapshot plus model `finishTermination()` are both required: joining the Notes task alone does not prove every native context has drained.

## AppKit and failure contract

The current App delegate selects the injected private Notes service/runtime, calls `service.beginTermination()` before returning `.terminateLater`, awaits those exact Notes tasks in its existing `nativeTerminationTask`, and finally asks `runtime.finishTermination()` for the real drain Bool. The existing optional `finalReply`/`safetyDrain` path on other diagnostic tuples shows how to veto once, consume the same callback, and request the second quit without another waiter. A Notes-specific optional callback must remain subordinate to `drained && ...`; it cannot turn false into true or clear task ownership before the measured first reply. The second Cocoa pass and `applicationWillTerminate` need actual reply/task/trace evidence. A failed runtime drain cannot be counted as clean exit simply because an observer ran.

The generic native arm catch in `NextNotesApp.runRequestedSelfTest` marks FAILED and calls `SelfTest.requestTermination()`. That is unsafe as an *invalid-input* fallback for an active-native prerequisite: it may quit with shared/default runtime selection after partial fixture preparation. Exact copied-model/root/output validation must happen before `NSApplication.shared`; any later failed model configuration, provider, meeting/transcript seed, or delegate tuple mount must report INVALID and exit before requesting Cocoa quit. This is a diagnostic failure path only; it is no proof of normal product shutdown. The existing standalone arm performs much of its model/meeting setup after AppKit starts, so a new stronger pre-owner admission is real work, not a documentation rename.

The App's ordinary quit path still constructs some cheap empty shared owners (`S1MiniRuntime`, `EmbeddingRuntime`, `LlamaBackend`, ASR/diarization owners) and invokes their termination methods. For this isolated Notes case, verify each does no model/download/owner-store work and retain the private Notes selector. `EmbeddingRuntime.shared` is constructed with `modelURL: nil`; its captured `NotesModelRuntime.shared` reference sits in a closure and is not an immediate model load. A private empty embedding tuple would narrow the experiment further if existing diagnostic tuple selection can admit it, but no new audio/model owner or second drain channel is warranted by source alone.

## Scope of proof

A future original/fixed native run could prove the exact private Notes task and an actual `llama_decode` bracket are present at the Cocoa boundary, that the same captured task returns, and that the runtime reports real drain before final exit. It would not prove all background Manager, Capture, Pocket/Kokoro, scheduled, frontend, or physical audio shutdown. The imported-pending Manager diagnostic has an empty live map and cannot substitute for this active native prerequisite. No source patch or executable verdict is offered here.
