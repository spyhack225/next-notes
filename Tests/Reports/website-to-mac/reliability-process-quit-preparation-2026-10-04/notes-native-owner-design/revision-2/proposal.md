# Existing NotesService operation: genuine native/Cocoa prerequisite design

Status: **REVISED PROPOSAL / HELD**. Revision 2 supersedes the draft safety callback array/repeated-join proposal; the earlier draft is retained unchanged for audit. Source inspection only. No canonical edits, compiler, native execution, model-file access, copy/download, owner store/default read, installation or owner quit. This is an existing NotesService operation design. It does not establish Manager, Capture, speech, full-process safe quit or speed acceptance.

## 1. Use the existing producer and owner

Keep the actual path: `NotesService.summarize` assigns its Task into `tasks[meeting.id]`, then `generate` uses its injected nonnil provider resolver and real NotesGenerator. The provider remains real `LlamaLLMProvider(runtime: privateRuntime)`. No scripted closure, substitute completion, new operation owner or additional ledger is justified. Existing `NativeTerminationSelfTest` already exercises this path with synthetic transcript data and disabled memory/file/cloud retrieval.

`NotesService.beginTermination` captures the same Tasks before cancelling them. AppDelegate joins those handles in its existing `nativeTerminationTask`. The operation's defer clears the same map entry only on actual Swift Task return. Bind the synthetic meeting UUID, the new private service and the private runtime before requesting quit. Exactly one summarize call on that previously empty private service creates exactly one map entry. At actual Cocoa entry, the existing count getter must still report one. The synchronous beginTermination call closes admission and captures that sole exact Task; no subsequent task can replace it, and App awaits the captured array. The explicit service/UUID/single-admission source contract makes this stronger than a bare generic map-count assertion.

**No new Task getter or registry is justified for this one-operation case.** Existing private service construction, summarize admission, the sole map entry, beginTermination snapshot and existing captured-array join supply the exact retained operation. Preserve those call sites. If the test later admits multiple operations, this single-operation proof no longer applies; review that real need before adding a seam. No bug or native RED has been reproduced here.

## 2. Bootstrap admission before NSApplication and AppDelegate

Reject missing/duplicate model flags, mixed startup/recording/other-owner/background modes, unknown flags and malformed output/timeout fields before creating AppKit or owners. Keep other modes' existing validation contracts and do not widen their admission.

Retain a small immutable admission value containing the canonical direct temporary UUID model root, explicit `fixture.gguf` URL, approved public fixture identity/expected byte count, a separate fresh direct temporary `NextNotesMeetingResumeTest-UUID` root, exact synthetic meeting UUID and confined output URL. This is a diagnostic input value, not another store or owner. Require raw and standardized/resolved paths to agree. Reject symlinks/nonregular files, existing meeting roots (including dangling symlinks), wrong filename/UUID/parent and inconsistent output paths. Runtime root supplies an already copied source-pinned public artifact; this thread does not inspect or copy weights. Content identity qualification belongs to that serial asset preparation. File size alone cannot establish public identity. Mount with `MeetingStore.isolated(at:)` only after the additional absence/raw-path checks; its general reopening seam alone permits existing directories and normalizes links.

After admission, use existing explicit constructors with supplied private values. Do not initialize NotesService.shared or use default `MeetingStore.shared`, `.live` context assembler or `.shared` provider runtime. Disable retrieval exactly as the existing fixture does. Before installing the delegate tuple or starting summarize, arm failures classify INVALID and terminate the diagnostic through a narrowly scoped fail-closed path, never the generic catch's `SelfTest.requestTermination` fallback into shared shutdown. Before native entry no weights are outstanding; after native entry, fail-close must preserve the configured private shutdown/cleanup path rather than call `exit` over live native work. Revalidate admission on mounting; validation timing is not atomic filesystem identity protection.

Use existing `NotesModelRuntime.configureTerminationNativeFixture(modelFile:observer:)` on the explicit private runtime before any countTokens, complete, stream, prewarm or load. It requires the exact diagnostic, canonical temporary model directory, unloaded model, nil loadTask and no native owner, and checks regular-file size. The admitted override is already used by the load availability check, `openNative(...fileURL:)` and GGUF metadata read. Saved model adoption is refused for this exact SelfTest mode by `adoptSavedSelectionIfNeeded`; no additional provider/model-choice store is needed.

The NotesService injected nonnil provider route does not call provider availability in the inspected production path: NotesGenerator invokes real generation/counting on the supplied provider. `LlamaLLMProvider.unavailableReason` independently reads `activeSpec().isDownloaded` and is **not** confined by the load override. Do not call that member as a fixture readiness check. Any reuse for Manager/planner requires a separate actual call-site/availability producer review; this design does not grant that route. Explicit nil failure sink and a supplied benign pressure snapshot are justified existing constructor arguments; neither turns load into a fake. Global scheduler/backend/residency/embedding cooperation remains real process-local production work and must be reviewed by the sole native owner before running.

## 4. Require real native admission and overlap

Reuse the existing observer around the actual `llama_decode`; keep both pre-call entry and actual native return/status. The trace lock contains scalar bookkeeping only; no callback I/O, parked native call, fixed delay, simulated native event or model pass. Schedule the real `NSApp.terminate(nil)` through the existing RunLoop callback after an earlier successful decode and a subsequent genuine entry.

At the actual first Cocoa `.terminateLater` observer require: admitted input, the previously empty private service with its exactly-one fixture admission, ownedTaskCount equal to one after the actual beginTermination capture, a previously successful native return, and an outstanding actual decode bracket. The asynchronous RunLoop handoff can miss a short decode. Missing overlap or missing captured operation is INVALID, not producer RED; never lengthen or hold native work to force it. Natural scheduling may require another independently labelled run by the serial owner, not automatic retry inside this fixture.

## 5. Observe actual return and actual exit votes safely

Propose adding optional `finalReply`, readonly `didVote(realDrained:actualAllowExit:)` and one-shot `safetyDrain` members to the **existing** Notes termination fixture tuple/configuration, following the already implemented other-llama diagnostic pattern. The readonly vote callback sits immediately before the existing sender.reply call and receives the actual producer-computed Booleans. It is required because the real `drained && ...` conjunction short-circuits: finalReply alone cannot observe a false real-drain vote. didVote only records bounded scalar diagnostics; no await, save, additional store/query, vote promotion or second App reply. Default nil preserves ordinary behavior. No second termination Task or waiter.

The actual final admission remains `real drained && every diagnostic veto`; include the optional Notes veto in that conjunction. No diagnostic may promote false runtime drain. Measure the first final vote before cleanup: actual entry/return balance, zero outstanding native bracket, actual Notes map cleanup, resumable synthetic meeting status and no generated note. Require the exactly-one admitted private operation to be the original fixture binding and the existing App snapshot to contain one Task. Force the first final diagnostic vote false once to verify the actual Cocoa veto path, even if all producer measurements pass. Record producer failures separately from deliberate veto.

Reuse the same nativeTerminationTask's existing cleanup continuation after the measured veto and only under its existing `drained` guard. Consume both optional safety callbacks at most once; reject mixed fixtures rather than compose parallel cleanup. Preserve the existing `for task in ownedNotesTasks { await task.value }` join BEFORE runtime.finishTermination and the first final vote. That existing join supplies actual same-operation return evidence; a second Task.value await would add no proof. The Notes safety callback therefore only rechecks the already measured native/private-store state after the deliberate veto; it creates or joins no Task and adds no sequential await. The other-llama callback signature remains unchanged; mutually exclusive fixture admission permits selecting one local continuation at the existing cleanup seam. It must not start a fresh summarize/model pass or mutate measured history. Clear the exact consumed callback, then use the existing one-shot re-quit route. The second final vote may allow only if real drain and all actual predicates are true. Check two observed `.terminateLater` replies, one first final veto, one successful second final vote and real `applicationWillTerminate` receipt. A false real drain must never be made successful by cleanup or diagnostic reply; it leaves that run failed/held under the runtime owner's owned-process disposition contract.

A failed original can be safely characterized only if its actual producer and byte-identical common cleanup have separately been qualified as safe. This revised proposal relies on the current existing captured-array join; it is not a cleanup contract for an original that omits that join. Do not use this design unchanged to run such an original, and do not add a redundant join to the current path to hide that missing prerequisite. Do not reuse an incompatible historical crashing binary or claim the existing seven-check Notes proof is a new RED. Original/fixed must use byte-identical COMMON inputs/assertions/observers and vary only the nominated responsible producer. No new producer repair is proposed here.

## 6. Required controls before qualification

- Malformed/mixed/duplicate flags and wrong/missing/symlink/existing/unconfined artifact/store/output paths refuse before AppKit/private owners. These are INVALID inputs, not permission to fetch a model or read owner data.
- Same fixture with missing natural native overlap is INVALID. A trace with prior success but zero active decode cannot pass the entry gate.
- Exact retained Task, actual NotesService map and native begin/end hook sensitivity; canceled Task alone, empty waiting map or returned wrapper cannot satisfy them.
- Actual final vote sensitivity: force diagnostic false while real drain true; real drain false can never pass. Same one-shot cleanup cannot loop or change the first measurement.
- Private store fresh reader verifies resumable status/transcript and no notes, with fixture roots retained for evidence. This is a fresh cache over private files, not process-crash/power-loss proof. Known-root cleanup only by the serial owner's retention policy after evidence capture.
- Installed/staged same COMMON original and fixed; actual production path, unchanged relevant native/permission/voice/owner-isolation regressions; true result logs and any crash retained. No source-only simulation substitutes for these.
- Ordinary recording choice stays first; rejected Keep Recording changes no owner. Normal voice Done remains background-friendly; Stop stays immediate; existing full-duplex/bounded-wait behavior is unchanged. SIGTERM/global destructor behavior is outside actual Cocoa proof.
