# UX-00 Agent slice: typed answer and read → action → approval → result

2026-10-01. Source audit of the current shared checkout. This is **one slice** of UX-00, not its four-journey visual sign-off. The Agent, task, and iMessage source files were already dirty and changing concurrently; this audit changed none of them. Evidence below describes the inspected source, not a captured running app.

## Current path and event sources

| Moment | Current producer → consumer | Current versus desired experience |
|---|---|---|
| Type and send | `AgentView.send()` reads and clears the draft, starts `RealtimeAgent.handleLive`; `handleLive` calls `handle`; `AgentSession.recordUser` appends the row and persists the conversation; `AgentView.timeline` renders it. (`AgentView.swift` 612–691; `RealtimeAgent+ToolLoop.swift` 328–331; `RealtimeAgent.swift` 274–351, 1252–1264, 1400–1418) | The request has a real row and the composer stays present. Acceptance is not inserted in the button handler; it occurs after the async entry and, for ACP requests, after `waitForACPConfirmation`. No measured send → visible-row latency yet. Session save is a synchronous main-actor section. |
| Working | `RealtimeAgent.beginWork` sets `isThinking`/`progressTitle`; `AgentView.thinkingRow` uses those plus `AgentActivityStore.liveAvatarState`. A background task starts in `AgentTaskManager.submit`, projects steps through `AgentActivityStore`, and renders `AgentWorkingCard`. (`RealtimeAgent.swift` 605–610; `AgentView.swift` 249–269, 505–522; `AgentTaskManager.swift` 43–67; `AgentActivityStore.swift` 46–83) | Real state already exists. The pane can show both a thinking row and a live task card, so visual duplication must be assessed in an actual run. Step labels come from `AgentActivityProjector`, not parsed from progress prose. |
| Model answer | The typed first-pass provider yields chunks into `assembled` inside `runModelTurn`; `AgentToolSpeechTracker` may send safe chunks to TTS during a voice session. The pane gets the assistant row only when `RealtimeAgent.finish` calls `AgentSession.recordAssistant`. (`RealtimeAgent+ToolLoop.swift` 655–713, 174–214; `RealtimeAgent.swift` 757–789, 1269–1280; `AgentView.swift` 424–455) | The model **does stream**, but the typed pane has no partial-answer observation in this path. Do not animate a fabricated typewriter over the committed answer. | Read and prepare action | `AgentToolExecutor` resolves scope/authority and enters `ActionOrchestrator`; `AgentActivityProjector` supplies public titles. (`AgentToolExecutor.swift` 115–220; `AgentActivityProjector.swift` 1–62) | A read can proceed under existing policy; the UI should not add a read confirmation. | Approval request | `ActionOrchestrator` receives `.ask`, awaits `PermissionGate.ask`; `present` sets one `pending`, builds the review before showing it, raises the island, and records the ask. `AgentView` draws `ToolReviewCard` inline for a matching task or above the composer otherwise. (`ActionRuntime.swift` 568–603; `PermissionGate.swift` 23–62; `AgentView.swift` 300–377; `AgentWorkingCard.swift` 20–63) | One gate/store already feeds conversation and island. | Choice and execution | `ToolReviewCard` calls `PermissionGate.respond`; the gate checks readiness, clears `pending`, resumes the waiter, records the choice, then `ActionOrchestrator` merges edited arguments and records approval before `fire`. (`ToolReviewCard.swift` 180–254; `PermissionGate.swift` 103–152; `ActionRuntime.swift` 568–615) | The card is removed immediately by the existing state change; the work resumes on the same async operation. No separate persistent “You approved” acknowledgement is shown in the conversation except audit/event projection, and that should be checked visually. Never create a second gate or timer to simulate this phase. |
| Result | `RealtimeAgent.finish` appends a durable assistant message for a foreground turn. `AgentTaskManager.execute` saves status/result/artifacts and finishes activity for background work. `AgentWorkingCard.terminalCard` offers result/artifact/follow-up views, but `AgentView` switches terminal tasks to the plain `taskRow` inside collapsed Recent activity. (`RealtimeAgent.swift` 757–789; `AgentTaskManager.swift` 197–231; `AgentWorkingCard.swift` 240–320; `AgentView.swift` 254–276, 524–548) | The task result is retained, but its richer terminal card is currently unreachable through this pane. `terminalCard` also hard-codes `.modify` for retry risk (`AgentWorkingCard.swift` 236–246). UX-04 must resolve actual risk before exposing Retry. |

## Existing components to reuse

`AgentView` timeline, fixed composer, thinking row, `AgentWorkingCard`, `AgentActivityStore`/`AgentActivityProjector`, `ToolReviewCard`, `ToolCallReviewStore`, `PermissionGate`, `AgentTaskManager` task result/artifacts, and the island proposal built from the same pending review. The website `Hero.tsx` is an illustrated timed sequence (its own 1.7–6.5 second phases); production must follow the events above.

## Visual and timing evidence still required

- **No sanitized screenshot/video captured.** This checkout has no existing Agent journey fixture-render flag. `--selftest-agent-panes` checks labels/layout values and a hosted switcher, not a typed/review/result screen. Capturing the owner's running app could expose messages, mail or meeting content, so it was not used.
- **No first-visible-feedback or main-actor-stall number measured.** Existing `LatencyTrace` measures transcript → first model token and tool call → result; it is not send → row, work update → visible label, or choice → visible acknowledgement. `MainActorSection.run("session.save")` identifies one section to measure, but its duration was not measured here.
- Need light/dark, minimum/larger window, keyboard/VoiceOver, and a sanitized approval fixture on an unlocked Mac. Verify whether the thinking row and task card overlap in one real turn, whether the card stays reachable during long work, the exact approval acknowledgement, result navigation, and scroll behavior. `AgentView` unconditionally calls `scrollTo("conversation-bottom")` on new message/audit IDs (lines 290–295); test a reader scrolled up before changing it.

## Safe implementation scope after the remaining baseline

1. UX-02 can make accepted/work/answer states clearer using the current `AgentSession` and `AgentActivityStore`. Preserve Stop and P3-11 typed-turn ownership. Add no artificial typing or extra stream buffer; a partial-row change requires a producer-to-UI event contract and a production-path regression.
2. UX-03 can improve the existing review's hierarchy, accessible focus, and immediate choice acknowledgement. Keep `PermissionGate.respond` as the only approval boundary and `ToolCallReviewStore` as the one edited-argument source. Reads retain their current policy.
3. UX-04 can expose the existing terminal result and links in the conversation, while determining retry risk from the actual tool/action instead of the current `.modify` literal. Preserve the one task ledger.
