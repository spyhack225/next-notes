## Mounted children and callbacks in both layout candidates

`AgentView.body` creates two whole-section `ViewThatFits` alternatives. The `offersInspector: true` candidate conditionally builds `AgentInspector` when its `@AppStorage` Boolean is true; the plain candidate omits it. Both contain `AgentPaneSwitcherBar`, the selected pane, and, for `.conversation`, its scroll and composer. Source does not prove whether SwiftUI evaluates/keeps a measured alternative alive. The planned fixture must assume **both** candidate child effects can run until native evidence says otherwise.

- `AgentPaneSwitcherBar.onAppear` starts a MainActor `Task`, yields once and scrolls the selected tab into view. Its `.onChange` animates a scroll on pane changes. It does not ask a provider or launch work, but callbacks from both candidates cannot identify the selected one.
- `AgentView.conversation.onAppear` similarly yields and scrolls to the bottom; its scroll-geometry and message/activity observers update local reading state. These are layout callbacks, not first displayed frames. The existing held typed turn can change `respondingMessage` and trigger them in either candidate.
- `AgentInspector.onAppear` calls `reload()`: `AgentAuditLog.loadPersistedGroupedByDay()` explicitly returns empty under SelfTest; `ScheduleStore.shared` is per-process temporary and `reload()` reads its temporary schedule/draft files. Its `@State` also constructs identity (temporary under SelfTest), settings (harness suite), grants (empty under SelfTest), activity (memory), and permission/ACP gates (memory). The inspector's default Activity tab is otherwise read-only. Its `@AppStorage` tab binding remains an owner-preference risk without a diagnostic root override. No inspector button should be pressed in the observation.
- The conversation's `AgentSession.shared` is constructed with `fileURL: nil` under SelfTest; `AgentAuditLog.shared` starts empty; `NavigationState.shared` uses `SelfTestHarnessDefaults.shared`; `ModelLoadNotice.shared`, `PermissionGate.shared`, `ACPConfirmationGate.shared`, `ToolCallReviewStore.shared` and `AgentActivityStore.shared` are memory based for this path. `Settings.shared` uses the harness suite. These favorable routes do **not** override the task and installed-model owner reads above.
- With a precondition that `NavigationState.shared.agentPane == .conversation`, both approval gates have no pending request, and an isolated injected task manager is empty, the pane does not build `AgentWorkingCard`, `ToolReviewCard`, ACP confirmation, task input/file picker, Activity pane, About pane, MCP browser or provider action children. `answeringModelCaption` can still call `ModelRoleStore.resolution` after the scripted answer, which is why the library constructor must be isolated before any mount. Merely avoiding button clicks does not prevent `@State` construction.
- The existing `AgentPresentationSelfTest` injects a suspended scripted provider and already checks streamed text/Stop and `SelfTestStoreGuard` for owner **writes**. It does not currently assert an isolated task manager, library source, inspector preferences, fresh scene draft or mounted child effect set. Its successful marker cannot be reused to certify the new host without those new guards.

## Fail-closed admission and revised lease decision

The tentative **four-file lease** (`AgentPresentationSelfTest`, `AgentView`, `AgentAvatarView`, `ThemeVoiceGlow`) is **refused** for a shareable no-owner-read full-pane diagnostic. `AgentView` task-manager injection can be done through the existing constructor seam without changing global task-store semantics, but the independently eager `ModelRoleStore.shared` → `InstalledModelLibrary.shared` route remains. Inspector `@AppStorage`, draft scope and prewarm effects also require exact guards and native negatives. Expanding the Settings fixture's model-library route or changing global SelfTest semantics solely to count motion would violate the smallest-change goal. No off-source Swift patch is proposed because its safe pre-construction contract cannot be established within that scope.

Before any internal full-pane fixture could be admitted, require all of the following **before mounting**: exact self-test flag; temporary output/store paths resolved and checked against symlinks; an actual injected temporary task manager with no default shared-manager construction; a model-role/library source demonstrably bound away from owner files before `@State` initialization; inspector AppStorage suite selection proved with opposite owner/suite values; empty scene draft; conversation pane selected; both gates empty; no owner task rows; prewarm disabled only for this diagnostic; owner store/default snapshots before/after; and a negative proving each rejected configuration fails before host construction. If any item lacks a safe existing seam, stop. A post-mount scrubbed screenshot or unchanged-owner-write guard is not an isolation repair.

The smaller, still reviewable **normal-app sanitized Instruments route** remains: under a later authorized native slot, observe the current installed app with known harmless request/task inputs and metadata-only traces. It follows the actual `MainWindow`/Agent pane, so it can include task/approval, selected candidate, scroll, hide/minimize and later displayed-frame capture if access is granted. It must not expose owner text, filenames or model inputs in logs. Current Computer Use refusal blocks live interaction/capture; internal offscreen diagnostics are a different permission path and would establish only schedule/draw work in their own host, never visible compositor delivery. No native or latency green is claimed here.
