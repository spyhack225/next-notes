# F-01a — repair the gate evidence producer

The original read-only `python3 Scripts/dictation-stats.py --gates` crashed when
real hold rows were present. The full diagnostic also ignored D-14's second
condition: three dictation ASR starts waiting at least one second on the lane.
This is a diagnostic repair; no dictation/meeting execution behavior changed.

## Confirmed causes and retained changes

1. `main`'s early `--gates` branch called `stamp` before its local function
   definition. Moving the unchanged usage timestamp helper to module scope repairs
   both real callers, including the existing fallback timestamp formats.
2. `gate_verdicts` only checked whether any dictation feature had a `laneWait`
   key, and chose its proceed verdict solely from meeting overlaps. It never
   counted measured dictation starts. It now reads actual `dictation.asr` rows in
   the selected date range, counts finite nonnegative numeric waits ≥1 second,
   reports count/max/threshold, and evaluates that existing alternative condition.
   Missing, null, malformed, boolean, negative and nonfinite measurements cannot
   substitute for observed durations; hold/cleanup/meeting fields cannot stand in
   for the ASR producer. Known zero remains a measurement.

The existing 1-second dictation, 5-second meeting and three-occurrence thresholds
are unchanged. The original meeting-overlap route remains. No store, queue,
model pass, grant or pipeline delay was added.
