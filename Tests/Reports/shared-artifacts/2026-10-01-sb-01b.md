# SB-01b — adopt a verified legacy manifest alias before fetching (2026-10-01)

Status: bounded source and isolated/installed fixture verification complete. Parent SB-01 remains in progress.

## Confirmed producer failure and original regression

SB-01a deliberately decodes old installed rows with no checked-byte proof. The existing download producer only called the stat/current-proof `reusableModel` lookup. A runnable old file with exactly the requested bytes, imported under another basename, was therefore ignored at the pre-fetch boundary. It would proceed toward another transfer despite already having the artifact.

The red fixture uses actual three-byte `abc` contents at `old-custom-basename.gguf`, trusted SHA-256 for those contents, a legacy original ID/path/metadata with nil proof, and the real pre-fetch method body. Before the repair it returned nil, recorded no proof and could not resolve the row on manifest reopening. [Original red](2026-10-01-sb-01b/before.txt) ends `MODEL_ARTIFACT_FAILED` with all three assertions. No actual network/model transfer was used to reproduce this decision.

## Producer change

`ModelLibraryStore.run` now invokes `reusableArtifactBeforeDownload` before transfer and post-download policy. That method calls the existing library's `reuseOrVerifyArtifact` at this explicit download/adoption boundary. Provider/turn resolution keeps the read-only current-proof lookup.

A trusted normalized digest and positive byte count are required. A matching current proof takes the existing stat-only path. Otherwise, size-compatible legacy manifest rows are eligible only when present, non-auxiliary, non-built-in, with an opening verdict for the current backend tag and matching probe byte count. A detached utility task uses the actual existing verifier/hash, not a second downloader or queue. The existing hash loop now checks cancellation initially, per chunk and finally; cancellation forwards to detached verification and propagates as cancellation rather than checksum failure.

The library snapshots/rechecks original manifest metadata and file stamp before hashing, after awaits, on digest-mismatch failure, before writing proof, and before returning it. Removal, mutation, changed metadata or cancellation aborts before any further fetch/use. A stable digest mismatch preserves the file and may check another candidate. Only an actual matching proof is persisted, on the original row/ID/path with the original support and trial verdict. A failed manifest write cannot be reported as durable adoption. The real download caller checks the returned row/proof again before use/policy.

The existing explicit post-download policy remains in charge of a requested trial/switch/delete. Adoption itself does not choose a role, promote a trial, add a row/copy, change a default or select a model. No Settings, role, runtime, MiniCPM formatter, cleanup or notes-default code changed.
