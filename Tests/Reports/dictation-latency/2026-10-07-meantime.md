The owner asked for continued optimization while heavy native validation was held. This work removes pure CPU overhead without changing model choices, quality thresholds, formatting, dictionaries, file tagging, insertion or capture.

### Spoken-name scoring

The actual narrowing consumer scores each candidate against every contiguous window of up to six heard tokens. Its producer did unnecessary work inside that repeated search:

- After matching neither a stem token nor the candidate's own extension, it still searched every other extension's aliases before returning `.none`. It now returns the identical `.none` earlier.
- Other-extension evidence repeatedly iterated the immutable alias dictionary. An inverse lookup derived from that same table preserves every claimant, including shared aliases such as “typescript.” No contract constants changed.
- Approximate matching counted both Unicode token lengths even when the shared prefix was below the existing three-character floor. Those counts now happen only after that floor is met.
- Two arrays were allocated to count/locate consumed tokens in every window. One scan now computes the same count and span without those arrays.
- Search continued after a score of exactly one. Scores are clamped to one and the existing enumeration already follows earliest/shortest tie order, so the first perfect match can return immediately with the same evidence and offsets.

### File tagging

The tagger tokenized the same text twice and prepared all phonetic keys even for exact-only matches. It now prepares loose-match data only if a candidate needs it, reusing the exact pass's existing tokens once per tagging call. Every candidate, extension check, ambiguity rule, phrase boundary, UTF-16 offset, replacement and output style remains.

### Spoken structure

Every scan recompiled the fixed marker patterns. Each existing immutable `Pattern` now retains its compiled expression; matching still has independent per-call state and the priority/classification/rendering rules are unchanged.

The actual router's initial full-scope structure result already contains the exact marker predicate it obtained with a second scan. It now reads `beforeModel.markersSeen`. When final semantic text equals the original rule-cleaned input, it reuses the already-computed structure result instead of scanning that identical input again. Changed semantic text still goes through the normal post-cleanup structure pass.
