## Producer failures reproduced and repaired

1. **Premature sentence closure.** The controller used final rules on committed partial text. Those rules appended a full stop to an unfinished fragment. Incremental cleanup then treated that manufactured boundary as complete and consumed its sentence index. A later segment extending the same sentence invalidated the prefix even though ASR had changed none of its frozen words. Partial rules now omit final punctuation; ordinary final cleanup retains it. The actual controller producer and actual finishing consumer originally fail two assertions, then pass unchanged: two legitimate sentence cleanups are reused, with no repeated whole-dictation rewrite.
2. **Cancellation stopped admission, but not entered work.** The session set a Boolean without cancelling its group tasks. Cancel now reaches those same tasks. MiniCPM also checks cancellation after each bounded wait and before Apple fallback; a cancelled group returns instead of starting a competing fallback. The actual session/MiniCPM test originally left its admitted runner active, then passes with cancellation forwarded and zero fallback calls. Native completion is still distinct from caller return.
3. **Layout deadline joined an uncancellable responder.** The Apple planner used a throwing task group. Swift waits for cancelled children when that group exits, defeating the caller deadline when native work ignores cancellation. The same retained response now uses the existing bounded-wait gate, with cancellation forwarded. Budgets are unchanged. A blocked actual planner response originally fails the 150 ms caller bound, then passes. The fixture releases and joins its owned responder afterward; this is not a claim that all native work stops instantly.

4. **Discarded pre-clean was still running.** A rules route or rejected prefix abandoned its head without cancelling the same tasks. The replacement full cleanup could compete with work that could never be used. Both actual router paths originally fail their cancellation assertions, then pass after cancelling the discarded tasks. The fallback diagnostic now states that the final text did not match, rather than incorrectly claiming ASR must have changed it.

The first original staged router has four new failures; the additional discarded-head fixture has two. The corrected router passes those exact cases and the existing router suite. Original source snapshots and logs are retained in the task cache.

## Three additional producer repairs verified after resumption

### 5. Expired usable-head work survives delivery

`resolvePrecleanGroups` substitutes rules text after its shared grace. The usable-head branch preserves answers arriving during independent tail cleanup, then assembles an immutable result. Originally, unfinished groups remained entered and their queued successors could invoke the semantic formatter after neither answer could affect delivery. Cancelling the actual finishing router while its tail was blocked also failed to reach those head jobs.

The unchanged actual session/router fixtures produce **three failures** in `expiry-original-regressions.log`, then `CLEANUP_ROUTER_OK` in `expiry-fixed-regressions.log`. The router forwards outer cancellation to the same carried tasks, cancels leftover head work immediately after answer selection and on every return, and the existing incremental lane checks task cancellation before semantic entry. Completed answers arriving during the tail remain selected. The fixtures release and join their own held responders; no physical native-stop guarantee is inferred.

`CleanupRecord.precleanAnsweredGroups` is additive optional metadata. It counts nonempty completion boxes actually selected, including formatter fallbacks; it does not prove accepted semantic repairs. Legacy records/heads lacking boxes remain nil. The old group counter still means selected groups. Actual fixtures preserve late answered1 and expired selected2/answered0 distinctions. No extra queue, store, model pass or grace was added.

### 6. Native nonstreaming cancellation discards valid KV

The streaming/prefill producer already retains tokens successfully decoded before cooperative cancellation. `NotesModelRuntime.completeWhileScheduled`, used by actual dictation cleanup, instead cleared the entire context on every thrown error. Cancelled previous work could therefore make a resident second call pay its full prompt prefill again.

The maintained native prefix-cache fixture invokes the actual `completeForDictationCleanup` entry with a private existing S1 CPU context. It cancels its own task after the last successful native128-token prefill chunk, before sampling. Original `dictation-kv-original.log` is **LLM_PREFIX_CACHE_FAILED1**, reusing0 instead of649 tokens. With only the responsible catch corrected, `dictation-kv-fixed.log` is **LLM_PREFIX_CACHE_OK**: the successor reuses649 tokens, decodes one, and returns exactly the same nonempty output as the cleared-context control. Existing cache cases remain green.

Only `CancellationError` retains the successful native token ledger; genuine decode failures still clear native memory and that ledger. No incomplete answer becomes successful output. This proves the common runtime cache contract, not MiniCPM semantic quality, a new model/default, or the20tokens/s ASR+voice floor.

### 7. A superseded layout plan still delays authoritative rules

Stage D starts beside semantic cleanup. When post-cleanup spoken-structure rules produce final formatting, their output already has priority over any model plan. Originally the router nevertheless waited for the plan, then rejected it because those rules had rendered structure.

The actual router regression supplies mid-clause ordinals that only become renderable after semantic cleanup, with a deliberately held planner. Ordinary-prose layout still runs, all formatting/validation remains, and no deadline was shortened.
